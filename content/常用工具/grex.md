`grex` 能根据字符串样本自动生成正则表达式。我把它当作学习搭档：**先自己猜规则，再看工具如何表达，最后用新样本和反例检查自己的理解。**

- `grex`：根据样本**生成正则**。
- `grep` / `rg`：使用正则**搜索文本**，见 [grep 与 rg 笔记](常用工具/grep_rg.md)。
- 我主要记录命令行工具的用法，示例输出的核对版本是 `grex 1.4.6`；其他版本可能生成形式不同但含义等价的表达式。

> [!important] 样本不等于需求
> 默认设置下，grex 的目标是只匹配给出的样本，而不是猜出所有符合业务要求的字符串。开启 `-d`、`-w` 等选项后，匹配范围又可能大幅扩大。我仍需要自己判断“应该接受什么、必须拒绝什么”。grex 的 CLI 也没有输入负样本来约束生成的选项，反例需要另外测试。

## 安装与开始使用

先检查是否已经安装：

```bash
grex --version
grex --help
```

已有 Rust 工具链时，可以通过 Cargo 安装；下面是安装方法，已安装就不必重复运行：

```bash
cargo install grex --locked
```

不想编译时，可以从 [官方 Releases](https://github.com/pemistahl/grex/releases) 下载对应系统与架构的可执行文件。官方也列出了 Homebrew、Scoop 等包管理器渠道。`pip install grex` 安装的是 Python 扩展库，不是我这里记录的 Cargo CLI 安装路线。

不安装也能在 [官方在线演示](https://pemistahl.github.io/grex-js/) 中试用。不要向在线工具提交密码、令牌或真实的敏感数据。

## 命令速查

### 输入和输出

```bash
# 每个参数是一条完整样本
grex 'cat' 'car'

# 含空格的样本也要保持为一个参数
grex 'hello world' 'hello rust'

# 从标准输入读取，每行一条样本；末尾的 - 不能省略
printf '%s\n' 'cat' 'car' | grex -

# 从 UTF-8 文本文件读取，每行一条样本
grex -f samples.txt

# 用 shell 重定向保存正则；不是 grex -o
grex 'cat' 'car' > pattern.txt
```

上面的直接输入与管道示例可以在任意目录运行。文件示例需要当前目录已经有 `samples.txt`；`> pattern.txt` 会覆盖同名文件。位置参数与 `-f` 是两种互斥的输入方式，不要混用。

这里的单引号是 **shell 语法**：防止空格、`*`、`$` 等提前被 shell 解释，不属于传给 grex 的字符串。`grex '[a-z]'` 表示提供字面字符串 `[a-z]`，不是让工具展开一个正则。

### 常用选项

| 选项 | 长选项 | 作用与注意点 |
| --- | --- | --- |
| `-f 文件` | `--file 文件` | 每行读取一个样本，不是每行一条现成正则 |
| `-d` | `--digits` | 将 Unicode 十进制数字转换为 `\d`，会扩大匹配范围 |
| `-w` | `--words` | 将 Unicode 单词字符转换为 `\w`，字母、数字、下划线等都可能匹配 |
| `-s` | `--spaces` | 将 Unicode 空白字符转换为 `\s`，不只是普通空格 |
| `-r` | `--repetitions` | 将重复子串压缩为 `{n}`、`{m,n}` 等量词表示 |
| `-i` | `--ignore-case` | 生成忽略大小写的表达式，通常带 `(?i)` |
| `-g` | `--capture-groups` | 将默认的非捕获分组改成捕获分组，不会自动识别业务字段 |
| `-x` | `--verbose` | 输出带 `(?x)` 的多行易读表达式 |
| `-c` | `--colorize` | 彩色显示，供终端阅读；保存或传给其他工具时不要加 |
| `-e` | `--escape` | 将非 ASCII 字符输出为 Unicode 转义，不是“启用正则” |
| 无 | `--no-anchors` | 同时移除开头的 `^` 和结尾的 `$`，适合搜索较长文本中的片段 |
| 无 | `--no-start-anchor` | 只移除 `^`，保留结尾约束 |
| 无 | `--no-end-anchor` | 只移除 `$`，保留开头约束 |

其他字符类转换：`-D` → `\D`（非数字）、`-W` → `\W`（非单词字符）、`-S` → `\S`（非空白）。大小写不同，含义不同。

初学时一次只加一个选项，观察变化。短选项可以组合，例如 `-dr` 等价于 `-d -r`；同时使用 `-d` 和 `-w` 时，数字优先转换成 `\d`，其他单词字符转换成 `\w`。

## 正则语法小抄

先读懂本页会用到的符号，不必一开始背完整套语法：

| 写法 | 含义 | 例子 |
| --- | --- | --- |
| `^`、`$` | 匹配开头、结尾的位置，不消耗字符 | `^cat$` 用于限定整行内容 |
| `[abc]` | 匹配方括号中任意一个字符 | `[rt]` 匹配 `r` 或 `t` |
| `[0-9]` | 匹配一个 ASCII 数字 | `7` 可以，`x` 不可以 |
| `.` | 通常匹配除换行外的任意一个字符，具体取决于模式 | `a.b` 可以匹配 `a-b` |
| `\.` | 匹配字面上的句点 | `a\.b` 匹配 `a.b` |
| 分支（竖线） | 在多个分支中选择一个 | `cat` 或 `dog` 的写法见下文 |
| `(?:...)` | 非捕获分组：把一段表达式当成整体 | `(?:ab){3}` 匹配 `ababab` |
| `(...)` | 捕获分组：分组并保存匹配内容 | `(ab)` 可以供程序提取内容 |
| `?` | 前一个字符或分组出现 0 次或 1 次 | `colou?r` 匹配 `color`、`colour` |
| `*`、`+` | 前一个单元出现 0 次以上、1 次以上 | `a*` 可匹配空串，`a+` 不可 |
| `{n}`、`{m,n}` | 前一个单元出现指定次数、指定范围次数 | `\d{2}` 匹配两个数字 |
| `\d`、`\w`、`\s` | 数字、单词字符、空白字符类 | 范围受正则引擎和 Unicode 设置影响 |

上表竖线的实际写法：

```regex
^(?:cat|dog)$
```

> [!info] “整串校验”和“逐行搜索”不是完全相同的场景
> 在 rg 的默认逐行搜索里，`^`、`$` 对应行的边界。编程语言中，换行、末尾换行和多行模式会影响锚点语义；严格校验整个字符串时，优先使用目标语言提供的完整匹配接口，例如 Python 的 `re.fullmatch()`。

## 跟着示例学正则

以下命令均可在任意目录运行，不依赖练习素材。我练习时先预测输出，再执行命令对照。

### 第一步：公共部分与字符集合

```bash
grex 'cat' 'car'
# 输出：^ca[rt]$
```

拆开读：

1. `^`：从开头开始。
2. `ca`：这两个字符必须原样出现。
3. `[rt]`：最后一个字符可以是 `r` 或 `t`。
4. `$`：到这里结束，后面不能再接其他字符。

它匹配 `cat`、`car`，不匹配 `cap`、`cart`。**`[rt]` 是一个字符的位置，不是字符串 `rt`。**

### 第二步：可选字符与分支

```bash
grex 'color' 'colour'
# 输出：^colou?r$

grex 'cat' 'dog'
# 输出：^(?:cat|dog)$
```

- `u?`：`u` 可有可无，其他字符不变。
- `(?:cat|dog)`：在两条完整分支之间选择。
- 非捕获分组用于组织结构，不表示“提取一个字段”。需要提取时才考虑捕获分组。

为什么不是 `^cat|dog$`？因为它相当于“开头是 cat，**或者**结尾是 dog”，不是“两者任选其一且占满整串”。分组决定了锚点约束的范围。

### 第三步：字面字符与转义

```bash
grex 'log.1' 'log.2'
# 输出：^log\.[12]$
```

这里的 `\.` 必须匹配普通句点。如果我手动改成 `^log.[12]$`，`logX1` 也可能匹配。

grex 会按字面样本处理正则元字符，而不是把我输入的内容当作已有的正则。后面的示例出现 `\-` 也是工具输出的转义写法；在字符集合外，普通 `-` 通常可以直接书写。

### 第四步：从指定数字泛化为数字类型

保持样本不变，比较三个命令：

```bash
grex 'item-12' 'item-34'
# 输出：^item\-(?:12|34)$

grex -d 'item-12' 'item-34'
# 输出：^item\-\d\d$

grex -dr 'item-12' 'item-34'
# 输出：^item\-\d{2}$
```

| 表达式 | 匹配 `item-12` | 匹配未提供的 `item-99` | 匹配 `item-123` |
| --- | --- | --- | --- |
| 默认生成 | 是 | 否 | 否 |
| 加 `-d` | 是 | 是 | 否 |
| 加 `-dr` | 是 | 是 | 否 |

- **`-d` 改变匹配范围**：不再只接受样本里的数字值。
- **`-r` 在这里压缩重复写法**：把 `\d\d` 变成 `\d{2}`，不是让位数无限增长。
- 如果需求是“item- 后恰好两位 ASCII 数字”，可以手写成 `^item-[0-9]{2}$`。
- 如果需求是“一位或多位数字”，`[0-9]+` 就是我根据需求明确选择的规则，不能指望两个两位数样本让工具自动知道。

注意：`-d` 会转换样本中**所有**十进制数字，无法指定只转换某个业务字段。固定版本号、固定前缀里的数字也可能被泛化。

### 第五步：重复子串与次数边界

```bash
grex -r 'ababab'
# 输出：^(?:ab){3}$

grex -r 'ha' 'hahaha'
# 输出：^(?:ha|(?:ha){3})$
```

第一条表示整个 `ab` 重复 3 次，不是只重复 `b`。第二条仍然只允许 1 组或 3 组 `ha`，**没有凭空补出中间的 `haha`**，也不是无限重复。

进阶时可以用 `--min-substring-length` 控制最短重复单元长度，用 `--min-repetitions` 控制转换门槛；两者需配合 `-r`。后者按首个子串之后的额外重复次数计算，例如 `ababab` 是一个 `ab` 加两次重复。初学阶段保留默认值即可。

### 第六步：谨慎使用单词字符和空白字符

```bash
grex -w 'item-12' 'item-34'
# 输出：^\w\w\w\w\-\w\w$

grex -s 'a b' $'a\tb'
# 输出：^a\sb$
```

- `-w` 连固定前缀 `item` 也转换了，`xxxx-AB` 都能匹配。它不是“只泛化变量部分”。
- `\w` 不是“任意英文单词”，而是一个单词字符；在 grex / rg 的 Unicode 语义下，其范围也不限于英文字母。
- `\s` 不只是空格，还能匹配制表符等空白。`$'a\tb'` 是 Bash 写法，传入的实际内容是 `a`、一个制表符、`b`。
- `\d` 在 grex / rg 的默认 Unicode 语义下也不只限于 `[0-9]`。需要纯 ASCII 时明确写范围，并在实际使用的引擎中验证。

## 把生成结果交给 rg 验证

### 整行筛选：保留锚点

下面的样本包含原始正例、未见过但应接受的正例，以及位数、前缀和嵌入位置方面的反例：

```bash
pattern=$(grex -dr 'item-12' 'item-34')

printf '%s\n' 'item-12' 'item-99' 'item-1' 'item-123' 'other-12' 'prefix item-12 suffix' |
  rg -n -e "$pattern"
```

预期输出：

```text
1:item-12
2:item-99
```

这里 `"$pattern"` 的双引号保留变量内容，`-e` 表示后面是搜索模式。**不要加 `rg -F`**，否则会按普通文本寻找反斜杠、锚点等符号，而不是解释正则。

### 日志片段提取：移除锚点

```bash
pattern=$(grex -dr --no-anchors 'item-12' 'item-34')

printf '%s\n' 'INFO created item-12 successfully' 'WARN item-99 not found' |
  rg -o -e "$pattern"
```

预期输出：

```text
item-12
item-99
```

此处 `-o` 是 **rg 的选项**，表示只输出匹配片段；grex 没有对应的保存文件选项。

> [!warning] 去掉锚点，也就去掉了完整性约束
> 这个无锚点表达式还能从 `item-123` 中提取出 `item-12`。如果我需要提取完整编号，需要另外定义编号的左右边界并测试，而不是只删除 `^`、`$`。

## 在 Python 中检查正例与反例

仅验证“原样本都能匹配”很容易漏掉过度泛化。下面直接调用已安装的 grex，再用 Python 标准库测试，**不需要安装 Python 版 grex**：

```python
import re
import subprocess

pattern = subprocess.check_output(
    ["grex", "-dr", "item-12", "item-34"],
    text=True,
).strip()

# 这些期望来自需求：item- 后恰好两位 ASCII 数字。
cases = {
    "item-12": True,
    "item-99": True,
    "item-1": False,
    "item-123": False,
    "other-12": False,
    "prefix item-12 suffix": False,
    "item-１２": False,  # 全角数字：用来暴露 Unicode 范围问题。
}

print("生成结果：", pattern)
for text, expected in cases.items():
    actual = re.fullmatch(pattern, text) is not None
    status = "符合预期" if actual == expected else "需要修改规则"
    print(f"{status}：{text!r}，期望={expected}，实际={actual}")
```

预期最后一项显示“需要修改规则”：Python 默认的 `\d` 也能匹配全角数字。如果确实只接受 ASCII 数字，可以将 `pattern` 改为 `r"^item-[0-9]{2}$"`，再运行同一批测试。

这里故意保留一次规则与需求不一致的结果，目的是练习：**生成结果是起点，正反例才是判断依据。**

## 可读性与兼容性

### 先看懂，再复制

```bash
grex -x 'color' 'colour'
grex -i 'error' 'ERROR'
# 第二条输出：(?i)^error$
```

`-x` 输出的是带 `(?x)` 的多行正则，不只是把一行文本随意换行。该模式会让引擎忽略表达式中的部分空白，并支持注释语法。学习时方便阅读；传给 rg 的 `-e` 时，优先使用默认单行输出，因为 rg 需要额外配置才能接受模式里的实际换行。

### 不要假定所有工具都用同一种正则

官方说明生成结果兼容 Rust 的 `regex` crate；rg 默认使用同一类正则语法，因此我可以用它验证这里的示例。换到其他环境仍需测试：

| 使用环境 | 注意点 |
| --- | --- |
| `rg` | 不要用 `-F`；`-i`、`-w`、`-r` 的含义也不要和 grex 混记 |
| `grep -E` | 不原生支持 grex 常见的 `(?:...)`、`\d`、`(?i)` 等写法，不能原样照搬 |
| Python `re` | 本文基础模式可用，但 grex `-e` 可能输出的 `\u{...}` 不是 Python `re` 接受的同一种转义写法 |
| JavaScript | 不能照搬完整的 `(?i)`、`(?x)` 输出；大小写通常由外部 `i` 标志控制；字符类、Unicode 转义的语义也需单独核对 |

复制到代码字符串里时，还有“字符串转义”和“正则转义”两层问题。Python 用 `r"\d{2}"` 这样的原始字符串较直观；JSON 等格式通常还要把反斜杠再转义一层。

## 建议的学习顺序与练习

我准备每次只练一类语法，按 **预测 → 生成 → 拆解 → 测试 → 手改** 的顺序来。前面的内联命令无需创建文件；要保存素材时，统一放在练习场地，而不是笔记站的源码目录：

- 工作目录：`/home/errorichard/workspace/projects/learning/linux/tools-practice`。
- 样本文件：放在 `datasets/grex/`，如 `positive.txt`、`negative.txt`。
- 练习题与自己的解答：放在 `exercises/`，例如 `grex.md`。
- 这是我准备保存练习的目录约定，不代表这些文件已经创建。

### 第一轮：读懂输出

1. 执行 `grex 'a' 'b' 'c'`，解释输出中的范围。它会匹配 `d` 吗？
2. 执行 `grex 'abc' 'bc'`，找出哪个字符变成了可选项。
3. 用 `file.txt`、`file.csv` 生成表达式，解释句点为什么被转义。
4. 比较 `grex '22' '33'`、加 `-d`、再加 `-dr` 的输出；分别检查 `23` 是否匹配。

### 第二轮：判断泛化边界

5. 用 `user-01`、`user-02` 生成“固定 user- 前缀，后面恰好两位数字”的规则。加入 `admin-01`、`user-AA`、`user-001` 作为反例；比较 `-d` 与 `-w`。
6. 用 `a`、`aaa` 配合 `-r` 生成规则，测试 `aa`。不要只看 `{...}` 就猜它接受所有中间长度。
7. 用 `ERROR`、`error` 配合 `-i` 生成表达式，检查 `Error` 与 `ERRORS` 的区别。
8. 用日期样本生成正则，试试 `2026-99-99`。为什么“外形像日期”不能保证“日期真实存在”？

### 第三轮：自己写规则，再让工具做对照

先不用 grex，按需求写两条正则：

- 文件名为 `note-` 加恰好三位 ASCII 数字，以 `.md` 结尾。
- 文本只能是 `yes` 或 `no`，不接受额外的前缀或后缀。

再各取几个正例交给 grex，对比结构差异。不要为了“和工具输出一模一样”修改自己的正确规则；同一个匹配集合可以有不同的表达式。

每题至少准备：原始正例、未见过但应接受的新正例、长度反例、前后多字符反例。涉及数字或字母时，再考虑是否允许 Unicode 字符。
