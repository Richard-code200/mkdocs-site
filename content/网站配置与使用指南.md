## 1. 先理解：这个网站是怎么运行的

本站是一个**静态笔记网站**：你写 Markdown 文件，Quartz 把它们转换成浏览器能打开的网页，再由 GitHub Pages 托管。

```text
你维护的源文件
├── content/                 笔记正文
├── quartz.config.ts         全站配置
├── quartz.layout.ts         页面组件布局
└── quartz/                  框架、首页组件、样式、字体
            │
            ├── npm run build ──→ public/ ──→ GitHub Pages
            │                         正式构建结果
            │
            └── npm run serve ──→ .preview/ ──→ 本机浏览器
                                      本地预览结果
```

不需要数据库，也不需要运行后端服务。搜索、关系图、反向链接使用构建时生成的内容索引。

### 三个经常混淆的位置

| 位置 | 含义 | 你应该做什么 |
| --- | --- | --- |
| 本机源码仓库 | 你正在编辑的文件 | 写笔记、改配置、运行检查 |
| 本机预览 | 仅当前电脑可访问的测试站 | 确认页面效果，不会自动上线 |
| 线上网站 | 已发布的版本 | 内容以发布结果为准，不会读取本机未发布文件 |

- 正式网站：<https://richard-code200.github.io/quartz-site/>
- 源码仓库：<https://github.com/Richard-code200/quartz-site>
- 默认本地预览：<http://localhost:8082/quartz-site/>

> [!warning] 两条最重要的原则
> **修改源文件，不修改 `public/` 或 `.preview/`。**它们下次构建就会被重新生成。
> **提交、推送和发布是三件事。**`git commit` 只保存在本机；推送到 `main` 才会触发当前发布工作流。

### 2.3 维护、回归与生成物

| 路径 | 用途 | 注意 |
| --- | --- | --- |
| `scripts/serve.sh`、`scripts/serve.mjs` | 本地构建并提供子路径预览 | 默认仅监听本机 |
| `scripts/build_navigation.py` | 从排序表生成侧栏排序函数 | 改排序后运行 |
| `quartz/util/navigation.ts` | 生成后的侧栏排序函数 | 优先改 JSON，再生成，不要只改这里 |
| `scripts/validate_site.py` | 静态验收脚本 | 链接、旧路径、旧锚点、字体和发布网址检查 |
| `.github/workflows/publish.yml` | GitHub Actions 自动发布 | 决定何时构建、发布到哪里 |
| `package.json` | npm 命令、依赖范围、项目元信息 | 改构建命令或依赖时才需要碰 |
| `package-lock.json` | 精确依赖版本 | 不要手工编辑，不要随意删除 |
| `.node-version`、`.npmrc` | 开发环境约束 | 不要为了绕过报错随意改动 |
| `migration/manifest.json` | 旧站内容、锚点与字体回归记录 | 长期保留，新文章无需补登记 |
| `migration/迁移说明.md` | 历史迁移与恢复资料 | 处理迁移遗留问题时查看 |

| `.quartz-cache/`、`*.tsbuildinfo` | 构建和类型检查缓存 | 不是笔记，也不是备份 |
| `artifacts/` | 浏览器验收截图等 | 当前被 Git 忽略 |

`quartz/` 同时包含框架代码和本项目的定制文件。不要把它当成纯粹的第三方依赖整个替换，否则可能覆盖首页、字体和旧网址兼容实现。

## 3. 第一次启动与日常预览

### 3.1 核对运行环境

```bash
node --version
npm --version
python3 --version
```

本项目按 Node.js 22、npm 10 维护，其中 `package.json` 要求 npm 至少为 10.9.2。静态验证脚本只需要 Python 3 标准库。

没有这些命令，先准备相应运行环境；不要通过修改 `engines` 字段来掩盖版本不符合的问题，也不需要先全局安装 Quartz。

### 3.2 首次安装依赖

```bash
SHARP_IGNORE_GLOBAL_LIBVIPS=1 npm ci --no-audit --no-fund
```

- `npm ci` 按锁文件安装，通常用于首次获取仓库、锁文件变动后或重建依赖。
- 它会重建 `node_modules/`；不要把自己的文件放在依赖目录里。
- 前面的环境变量用于避免系统 libvips 让 `sharp` 意外进入源码编译，不会修改系统配置。
- 平时只是修改笔记，不需要每次都重新安装依赖。

### 3.3 启动预览

```bash
npm run serve
```

看到“笔记网站已就绪”后，打开 <http://localhost:8082/quartz-site/>。

这个命令会先构建 `.preview/`，再启动预览服务。终端持续占用是正常的；在该终端按 `Ctrl+C` 停止。

端口被占用时，换一个端口，不必结束不认识的进程：

```bash
PORT=8083 npm run serve
```

这时访问 `http://localhost:8083/quartz-site/`。

### 3.4 改完文件，怎样看到新效果

**最容易理解的方式：**停止预览，然后重新运行 `npm run serve`，再刷新浏览器。

**不用停止服务的方式：**保持预览终端运行，在第二个终端进入仓库根目录，执行：

```bash
QUARTZ_BASE_URL=localhost:8082/quartz-site npm run build -- --output .preview
```

等构建结束再刷新。使用 8083 时，这条命令中的端口也必须改成 8083。构建过程中的页面可能暂时不完整，不要在构建尚未结束时判断链接是否损坏。

> [!important] 本站的预览不是自动热更新
> 当前 `npm run serve` 是“先构建一次，再提供静态文件”。保存文件不会自动重建。
> 单独运行 `npm run build` 更新的是 `public/`，不是浏览器正在访问的 `.preview/`。

预览只绑定 `127.0.0.1`，不能直接从手机或另一台电脑访问。若要开放局域网，应另行评估监听地址和访问风险，而不是关闭防火墙。

## 4. 写一篇新笔记：完整示例

### 4.1 选择分类并新建文件

例如准备记录 Rust 的学习方法，在编辑器中创建：

```text
content/Rust/复习方法.md
```

保留现有中文分类和文件名。不必把所有文章改成英文，也不要顺便移动已有文章。

### 4.2 复制这个起步模板

下面是新文件的完整示例；日期请换成实际写作日期：

````markdown
---
title: Rust 复习方法
description: 用练习和回顾巩固 Rust 所有权知识。
tags: [Rust, 学习方法]
created: 2026-11-09
modified: 2026-11-09
---

这篇笔记记录我准备怎样复习 Rust。

## 本次目标

- 理解所有权转移。
- 分清借用和复制。

## 相关笔记

先复习[所有权](Rust/所有权.md)，再看[引用与借用](Rust/引用与借用.md)。

## 一个小例子

```rust
fn main() {
    let message = String::from("继续学习");
    println!("{message}");
}
```

> [!info] 复习提示
> 先自己解释一遍，再运行代码验证。
````

文件顶部两个 `---` 之间叫 **frontmatter（元数据）**，用于说明标题、日期等；下面才是正文。

- `title` 会生成文章大标题，所以正文通常从 `##` 开始，避免再写一个 `#` 标题。
- YAML 字段使用英文冒号，冒号后加空格；缩进用空格，不用 Tab。
- 标题含有英文冒号加空格等特殊内容时，用引号包住，例如 `title: "Rust: 所有权复习"`。
- 代码块语言标签使用小写，例如 `rust`、`bash`、`typescript`、`json`。

### 4.3 元数据常用字段

| 字段 | 用途 | 示例与提醒 |
| --- | --- | --- |
| `title` | 页面标题、搜索标题 | `title: Rust 复习方法`；不写时会退回文件名 |
| `description` | 页面描述及搜索摘要来源 | 一两句话概括内容，不必复制全文 |
| `tags` | 标签页和关联信息 | `tags: [Rust, 学习方法]`；不等于文件夹分类 |
| `created` | 创建日期 | `created: 2026-11-09`；建议明确填写 |
| `modified` | 修改日期 | 实质更新后手动修改，不会自动写回 Markdown |
| `draft` | 是否暂不生成文章 | `draft: true`；准备发布时删除或改为 `false` |
| `enableToc` | 是否为这篇文章生成目录 | `enableToc: false`；布尔值不要加引号 |
| `aliases` | 额外的站内跳转地址 | 见第 5 节，通常不需要设置 |

当前默认按 `created` 取日期，且日期插件优先使用元数据，其次才参考文件系统。**不要依赖“文件名里写了日期”来决定排序**，例如 `随记/2026-11-09.md` 仍建议填写 `created`。

当前页面布局只有在元数据含 `created` 时才显示文章的日期 / 阅读信息区域。缺少日期还可能导致换电脑后排序变化。

`_original_note` 和 `_generated_navigation` 是历史迁移或导航标记，普通新笔记不要复制添加。当前并未启用“只有 `publish: true` 才发布”的过滤器，**不要把 `publish: false` 当成保护隐私的方法**。

### 4.4 写完后会自动发生什么

重新构建后，正常的新文章会进入：

- 左侧“笔记导航”的目录树；
- 搜索索引；
- 关系图节点；
- 所在文件夹页面的自动文章列表。

有几点**不会自动发生**：

- 分类 `index.md` 正文中的手写推荐链接不会自动追加。
- `content/笔记导航.md` 正文中的分类入口和手写篇数不会自动更新。
- 首页不会自动为每个新分类增加一张卡片。
- 关系图有节点不代表一定有连线：连线来自真实站内链接。

### 4.5 草稿与隐私不是一回事

`draft: true` 会让文章不被当前 `RemoveDrafts` 插件发布，但它不是加密、登录或仓库访问控制：

- 草稿文件如果提交到公开 GitHub 仓库，别人仍能读取源码。
- 草稿引用的图片等附件可能独立被复制到站点中，不能假定一并保密。
- 已经发布过的内容，改成草稿也不能清除 Git 历史、外部缓存或他人的副本。

真正敏感的内容不要放进公开仓库；当前 `content/private/` 同时受到构建忽略和 Git 忽略，但仍应先确认文件没有在过去被跟踪。不要用 `git add -f` 强行加入私人文件。

## 5. 链接、图片与常用写法

### 5.1 站内链接以 `content/` 为根目录

不管正在编辑哪一篇笔记，推荐都写完整的内容库路径：

```markdown
[所有权](Rust/所有权.md)
[常用工具](常用工具/index.md)
[[Rust/所有权|所有权]]
```

这些链接中**不写** `content/`，不写本机绝对路径，也不必手工加上 `/quartz-site/`。

例如从 `content/随记/某一天.md` 链接到 Rust 笔记，仍然写 `Rust/所有权.md`，而不是凭文件夹位置猜相对路径。

链接到具体小节时，最稳妥的做法是在预览中点击标题旁的锚点图标，复制并核对实际地址。不要假设标点、空格、重复标题生成的锚点一定与自己的直觉相同。

### 5.2 图片与附件

推荐把公开附件放进清楚的目录，例如：

```text
content/assets/网站维护/预览截图.png
```

然后在笔记中使用下面的写法；这是示例路径，实际使用前需要放入对应文件：

```markdown
![本地预览窗口](assets/网站维护/预览截图.png)
[下载示例文件](assets/网站维护/示例.zip)
```

笔记图片放 `content/` 下便于与文章一起管理；全站通用的图标、字体等放 `quartz/static/`。注意控制截图大小，并在提交前检查是否包含用户名、令牌或私人窗口。

### 5.3 提示块、强调和任务列表

```markdown
> [!info] 普通提示
> 这里写说明。

> [!warning] 风险提醒
> 执行前先备份。

> [!important] 关键步骤
> 完成后再继续。

==需要重点记住的内容==
~~已经过时的说法~~

- [ ] 尚未完成
- [x] 已完成
```

本站使用 Obsidian callout，不要继续新增 MkDocs Material 的 `!!!` 或旧的 `///` 提示块语法。任务列表可以渲染，但当前没有开启点击复选框来保存笔记的功能，修改状态仍应编辑 Markdown。

本站当前没有在 `quartz.config.ts` 中启用 `Plugin.Latex()`；不要仅凭通用教程就假定数学公式插件已经生效。需要添加新的语法插件时，先了解依赖和构建影响，再单独验证。

### 5.4 标题、文件名和网址是三件事

```text
源文件：content/Rust/所有权.md
文章名：由 title 决定
常规网址：https://richard-code200.github.io/quartz-site/Rust/所有权.html
分类页：https://richard-code200.github.io/quartz-site/Rust/
```

修改 `title` 通常不会改变网址；修改文件名或移动目录会改变网址，也会影响已有链接。

对于**迁移后新增的文章**，若确实要从 `Rust/复习方法.md` 改名为 `Rust/复习清单.md`，可以在新文件中保留旧的内容路径别名，片段如下：

```yaml
aliases:
  - Rust/复习方法
```

当前别名生成器会为这个额外路径输出 `.html` 跳转页。别名不带域名、不写 `content/`，也不要与现有页面冲突。改完更新站内链接并验证旧地址。

**不要直接套用这个办法随意改名迁移清单中的原站文章。**原站文件位置、旧目录网址和标题锚点受 `migration/manifest.json` 约束，移动它们需要同步评估兼容性。

## 6. 分类、导航和阅读顺序

本站有几套名字相近、但相互独立的“导航”：

| 你看到的位置 | 谁控制 | 新文章是否自动出现 |
| --- | --- | --- |
| 左侧目录树“笔记导航” | 内容目录 + `sortNavigation` | 会，重新构建即可 |
| “学习笔记”页面正文 | `content/笔记导航.md` | 手写链接不会自动追加 |
| 分类页顶部介绍、推荐链接 | `content/某分类/index.md` | 手写部分不会自动追加 |
| 分类页下方文章列表 | Quartz 的 `FolderPage` | 会 |
| 首页顶部菜单和学习卡片 | `HybridHome.tsx` | 不会自动增加入口 |

分类页出现手写文章链接，又在下面出现自动列表，是这两种内容同时存在，不一定是构建错误。

### 6.1 新建一个分类

假设以后需要“网站维护”分类：

1. 在 `content/` 新建 `网站维护/` 文件夹。
2. 创建 `网站维护/index.md`，设置 `title` 并写几句分类介绍。
3. 把新笔记放在这个文件夹中。
4. 在 `content/笔记导航.md` 增加分类链接：`[网站维护](网站维护/index.md)`。
5. 希望固定侧栏位置时，再把分类加入 `site.navigation.json` 并生成排序函数。
6. 需要首页卡片时，另外修改首页组件；新分类本身不要求修改首页。

分类 `index.md` 示例：

```markdown
---
title: 网站维护
---

记录网站的写作流程与维护经验。
```

当前“学习笔记”页仍有迁移时手写的“53 篇”及分类篇数，不是实时统计。增加文章后如要维护它们，应重新清点；也可以把介绍改成不含固定篇数的文字，避免长期失真。不要把旧数字当作最新实际数量。

### 6.2 调整左侧栏的顺序

编辑 `site.navigation.json`：

- 最外层数组的先后决定已登记分类的顺序。
- 各分类 `files` 数组的先后决定已登记文章的顺序。
- 路径相对于 `content/`，包含 `.md`，大小写要与实际路径相同。
- 未登记文章仍然显示，通常排在其分类已登记文章后，再按名称比较；未登记分类也不会因此消失。

下面是**一项分类的片段**，不是完整 JSON 文件：

```json
{
  "title": "Rust",
  "folder": "Rust",
  "files": [
    "Rust/所有权.md",
    "Rust/引用与借用.md",
    "Rust/复习方法.md"
  ]
}
```

只登记实际存在的文件。JSON 必须用双引号，不允许注释，最后一项后面不加逗号。

修改后运行：

```bash
python3 scripts/build_navigation.py
```

它会更新 `quartz/util/navigation.ts`。如果要提交排序调整，**JSON 和生成后的 TypeScript 文件一起提交**。

> [!info] 这个脚本不负责生成分类正文
> `build_navigation.py` 只生成侧栏排序函数，不会重写 `content/笔记导航.md` 或各分类 `index.md`。
> 当前排序逻辑也不读取 JSON 的 `title` 来重命名侧栏；分类显示名称通常应在对应 `index.md` 的 `title` 中调整。

侧栏顺序、分类正文中的手写顺序、分类页自动列表的顺序并不相同。自动列表目前优先文件夹，再按配置的日期倒序等规则排序；改 `site.navigation.json` 不会同步改变它。

## 7. 修改全站基础配置

打开 `quartz.config.ts`。它是 TypeScript，不是纯 JSON：可以有注释，字符串通常用引号，布尔值是 `true` / `false`，对象条目间用逗号分隔。

### 7.1 常用设置对照表

以下都在 `configuration` 对象中：

| 设置 | 当前值 | 修改效果 / 注意事项 |
| --- | --- | --- |
| `pageTitle` | `Richard的个人博客` | 首页品牌名、侧栏站名等；不等于首页大字 `RICHARD` |
| `pageTitleSuffix` | ` · Richard的个人博客` | 浏览器标签页标题后缀，注意保留或调整前导分隔符 |
| `locale` | `zh-CN` | Quartz 界面翻译和日期格式，不会翻译笔记正文 |
| `baseUrl` | 默认 `richard-code200.github.io/quartz-site` | 分享链接、RSS、站点地图等绝对地址基础；不带 `https://` |
| `enableSPA` | `true` | 站内切换时减少整页重载；自定义交互需要适配 SPA 生命周期 |
| `enablePopovers` | `true` | 鼠标悬停站内链接显示预览 |
| `analytics` | `null` | 当前不启用访问统计；不需要就保持原样 |
| `ignorePatterns` | `private`、`templates`、`.obsidian` | 构建时忽略对应模式；不是 Git 忽略或访问权限设置 |
| `defaultDateType` | `created` | 组件取日期的默认类型，影响最近随记和列表排序等 |

例如，只想关闭悬浮预览，就把现有这一行改为：

```typescript
enablePopovers: false,
```

这是对象内部片段，不要单独粘贴到文件结尾，也不要把整份配置替换成这一行。保存后重新构建并检查文章链接的悬停行为。

### 7.2 环境变量是什么

当前 `baseUrl` 这样定义：

```typescript
baseUrl: process.env.QUARTZ_BASE_URL ?? "richard-code200.github.io/quartz-site",
```

意思是：本次构建提供了 `QUARTZ_BASE_URL` 就使用它，否则使用正式网址。

```bash
QUARTZ_BASE_URL=localhost:8082/quartz-site npm run build -- --output .preview
```

在 Bash 中，这种前缀只对这条命令生效，不会永久修改网站配置。不要为了预览把正式默认网址改成 localhost，也尽量不要在 shell 中永久 `export QUARTZ_BASE_URL=localhost:...`。

如果不确定当前终端是否残留了变量，可以检查：

```bash
printenv QUARTZ_BASE_URL
```

没有输出通常表示未设置；若存在不想要的临时覆盖，在当前终端执行 `unset QUARTZ_BASE_URL` 后再构建生产版本。

### 7.3 域名或仓库名变化，不是只改一个字段

未来更名仓库、改项目路径或启用自定义域名时，至少检查：

- `quartz.config.ts` 的正式 `baseUrl`。
- `quartz.layout.ts` 的 GitHub、RSS 页脚链接。
- `package.json` 的 `homepage`、`repository` 等项目元信息。
- `scripts/serve.sh`、`scripts/serve.mjs` 的默认预览子路径。
- `scripts/validate_site.py` 中 `BASE`、`SITE_URL`、`REPOSITORY_URL`。
- 浏览器验收脚本、README 和笔记里明确写出的站点网址。
- Git 远程、GitHub Pages 设置、自定义域名及旧地址跳转方案。

这是跨文件和线上配置变更，应先备份、列出旧新地址映射并单独验证。**只改 `baseUrl` 并不构成完整迁移**，也不应为了让验收通过而随意删掉网址检查。

## 8. 首页：视觉页面与 Markdown 摘要要区分

### 8.1 为什么改首页 Markdown，画面可能没变

本站根首页使用定制组件，不是直接渲染 `content/index.md` 的正文：

| 想修改什么 | 应修改哪里 |
| --- | --- |
| 首页摘要、搜索描述、文字链接关系 | `content/index.md` |
| 大字 `RICHARD`、介绍、按钮文案、关于区文字 | `quartz/components/HybridHome.tsx` |
| 顶部“学习笔记 / 随记 / 排版预览”菜单 | 同文件的 `HomeHeader` 部分 |
| 三张学习分类卡片 | 同文件顶部的 `topics` 数组 |
| 首页字号、颜色、间距、手机排版 | `quartz/components/styles/hybridHome.scss` |
| 文章页是否显示侧栏、目录、日期等 | `quartz.layout.ts` |

**变更首页入口或主要介绍时，两处要同步：**视觉组件和 `content/index.md`。否则浏览器看到的内容可能与搜索摘要、链接关系不一致。

只改首页文案时，在编辑器里搜索现有文字并小范围替换，避免误删 `<div>`、`</section>`、花括号或括号。

### 8.2 修改学习卡片

`HybridHome.tsx` 顶部的 `topics` 每个对象代表一张卡片，以当前 Rust 卡片为例：

```typescript
{
  slug: "Rust/index",
  prefix: "Rust/",
  title: "Rust",
  description: "从所有权到切片，理解语言背后的规则。",
  category: "编程语言",
},
```

- `slug`：点击卡片去哪里，**不带 `.md`、`.html` 或 `content/`**。
- `prefix`：统计哪些笔记，末尾的 `/` 用来匹配该分类路径。
- `title`：卡片标题。
- `description`：简介。
- `category`：卡片底部显示的分类文案，不负责创建真实目录。

改变现有卡片文字和目标路径，比盲目复制整个组件更容易维护。若要新增第四张卡片，还要检查渲染中的 `["Rs", "$_", "//"][index]` 对应的装饰标记数组，并检查网格与手机布局；`topics` 并不是唯一涉及卡片数量的地方。

卡片的篇数按组件筛选后的文章与 `prefix` 自动统计，不是直接统计磁盘文件总数。

### 8.3 “最近记录”显示规则

当前首页不是“全站最近文章”，而是：

1. 筛出 `随记/` 下符合首页文章筛选条件的笔记。
2. 按 `getDate` 取得的日期倒序排列，当前默认是 `created`。
3. 使用 `.slice(0, 2)` 只取两篇。

想显示四篇，把这一处 `.slice(0, 2)` 改成 `.slice(0, 4)`；这只是数量调整。其他分类的文章不会因为日期最新就出现在这里。

想按修改日期显示，需要同时理解全站 `defaultDateType` 的影响，不要为了首页需求直接改掉所有列表的日期规则。

### 8.4 首页全站图谱

首页图谱复用 Quartz 的站点索引，包含分类页和孤立页面；不会扫描 `content/` 之外的个人文件。新文章需要重新构建，线上还需要发布后才会出现。

首页组件里的图谱设置包括：

```typescript
localGraph: { depth: -1, showTags: false, focusOnHover: true, autoResize: true, autoFit: true },
globalGraph: { showTags: false, autoResize: true, autoFit: true },
```

- `depth: -1`：内嵌区域展示全站范围。
- `showTags: false`：不显示标签节点。
- `autoResize`：跟随容器尺寸变化。
- `autoFit`：初始视野尽量容纳全图；用户操作后保留视野。

首页图谱高度在首页 SCSS 的 `.preview-graph` → `.graph-outer` 中配置，桌面当前为 `460px`，手机规则下为 `320px`。文章页图谱是另一份布局配置，不要混淆。

## 9. 文章布局：搜索、侧栏、目录、页脚

打开 `quartz.layout.ts`，可以把它理解成“把现有组件放进页面的哪个区域”。

| 配置部分 | 控制什么 |
| --- | --- |
| `sharedPageComponents` | 公共 head、顶部 header、页脚等 |
| `defaultContentPageLayout` | 普通文章页布局 |
| `defaultListPageLayout` | 文件夹、标签等列表页布局 |
| `beforeBody` | 正文之前，例如面包屑、标题、日期、标签 |
| `left` | 左侧站名、搜索、阅读模式、文件目录树 |
| `right` | 右侧图谱、文章目录、反向链接 |

`noteOnly(...)` 是本项目的包装函数：根首页不输出这些文章页组件。不要为了让文章页出现某个组件，直接删除首页条件判断。

### 9.1 常见小调整

- **默认展开侧栏文件夹：**把 `Component.Explorer` 中 `folderDefaultState: "collapsed"` 改为 `"open"`。
- **调整侧栏标题：**修改同一处的 `title: "笔记导航"`。
- **关闭某篇文章目录：**优先在该篇元数据设 `enableToc: false`，不必改全站布局。
- **调整所有文章目录范围：**在 `quartz.config.ts` 的 `Plugin.TableOfContents()` 配置 `maxDepth`；当前默认收集到三级标题。
- **修改页脚 GitHub / RSS：**改 `Component.Footer({ links: ... })`。
- **移除某个侧栏组件：**只移除对应数组里的那一项，并确认逗号、括号保持成对。

目录默认需要超过一个符合范围的标题条目才生成，且文章目录组件套了 `DesktopOnly`：手机上没有右侧目录，并不一定是内容有错。

调整布局后，不仅检查文章页，也要检查首页、分类页和手机宽度。不要把“桌面文章页正常”当成全站都正常。

## 10. 外观与字体：从最小改动开始

### 10.1 调整正文字号与行距

打开 `quartz/styles/custom.scss`，先找到现有规则，例如：

```scss
article { font-size: 15px; line-height: 1.85; }
article p, article li { line-height: 1.85; }
```

想稍微放大正文，可以把现有 `15px` 改为 `16px`。若修改行距，记得同时检查段落、列表的单独规则；只改第一条可能仍被第二条覆盖。

文件底部还有手机媒体查询，当前文章字号为 `14px`。桌面改了不代表手机同步改变。代码块和表格也有独立字号，不会完全跟随 `article`。

建议一次只改一类属性，重新构建，然后打开[排版预览](排版预览.md)和一篇真实长文章检查。

### 10.2 为什么只改主题色可能没效果

本站是定制的 Gruvbox Dark，颜色不只来自一处：

1. `quartz.config.ts` 的 `colors` 为 Quartz 组件提供主题变量。
2. `quartz/styles/custom.scss` 有直接写出的正文、标题、代码块等色值。
3. `hybridHome.scss` 有首页自己的背景、文字和卡片颜色。
4. `quartz/static/styles/gruvbox_dark.css` 保留原站基础样式。
5. `quartz/util/previewTheme.ts` 决定代码 token 的高亮颜色。

所以只修改 `secondary` 不会让所有黄色标题都跟着变。先确认想改的是哪个区域，再改对应规则。

当前浅色和深色配置使用相同色值，并在 `Head.tsx` 中固定深色；这不是一个能靠添加切换按钮就完成的浅色主题。要支持真正的浅色模式，需要整体处理固定色值和主题初始化，属于另外一项改造。

### 10.3 字体维护

当前字体搭配：

| 用途 | 字体 |
| --- | --- |
| 西文正文 | MonaspiceAr |
| 西文标题 | MonaspiceXe |
| 代码 | MonaspiceNe |
| 代码注释与文档字符串 | MonaspiceRn 斜体 |
| 中文与后备字符 | Sarasa Term SC（更纱黑体） |

字体由站点自身提供，访客不必安装。本地普通构建也不需要安装字体转换工具。

**写新汉字通常无需重新生成字体。**已有 Sarasa 分包覆盖源字体支持的字符，并通过 `unicode-range` 按需加载。

如果只是改字号、行距，不要运行字体生成脚本。真正更换字体时需要同时考虑：

- `quartz.config.ts` 的字体设置。
- `custom.scss` 中的字体栈。
- 字体文件、`font_faces.css` 和 `code_fonts.css`。
- 字体许可证与源字体版本。
- `migration/manifest.json` 的字体校验记录。

详细操作在仓库 `scripts/字体资源维护.md`。更换字体或重分包会触发校验变化，应先确认差异符合预期，再维护回归记录，不要直接删除校验项。

### 10.4 图标与分享图

- 默认分享图来自 `quartz/static/og-image.png`；当前 `Head.tsx` 使用这一固定路径。
- `Plugin.Favicon()` 从 `quartz/static/icon.png` 生成图标，同时页面头部还声明了 `preview-favicon.svg`。
- 因此只替换 `icon.png`，浏览器标签上的 SVG 图标可能仍保持原样；需要核对两种资源及头部引用。
- 首页字母标志是 `HybridHome.tsx` 内的 SVG，不等于浏览器标签页图标。

修改后重新构建，并用强制刷新或新标签页检查。分享平台和浏览器可能缓存旧图，不应仅凭一次旧缩略图判断构建失败。

## 11. 插件：知道它们负责什么即可

`quartz.config.ts` 的 `plugins` 按三个阶段组织：

```text
transformers：读取、加工 Markdown 和元数据
      ↓
filters：决定哪些文章可以发布
      ↓
emitters：输出网页、索引、资源和兼容跳转
```

### 当前已启用的主要功能

| 插件 / 功能 | 作用 |
| --- | --- |
| `FrontMatter` | 读取标题、标签、日期等元数据 |
| `CreatedModifiedDate` | 优先使用元数据，其次使用文件系统日期 |
| `SyntaxHighlighting` | 代码高亮，使用本站 `previewTheme` |
| `ObsidianFlavoredMarkdown` | 双链、callout、高亮等 Obsidian 风格语法 |
| `GitHubFlavoredMarkdown` | 表格、删除线、任务列表等 |
| `LegacyAnchors` | 保留旧站标题锚点 |
| `TableOfContents` | 提取文章小节目录 |
| `CrawlLinks` | 处理站内链接与图谱关系，当前采用内容库根路径解析 |
| `Description` | 提供内容摘要 |
| `RemoveDrafts` | 过滤 `draft: true` 的文章 |
| `ContentPage` + `HybridHome` | 生成文章，并为根首页使用定制页面 |
| `FolderPage`、`TagPage` | 生成分类 / 文件夹页和标签页 |
| `ContentIndex` | 搜索与图谱索引、RSS、站点地图 |
| `Assets`、`Static` | 复制笔记附件和全站静态资源 |
| `AliasRedirects` | 为文章别名生成跳转页 |
| `Favicon`、`NotFoundPage` | 图标与 404 页面 |
| `LegacyRoutes` | 保留旧站目录形式的网址 |

日常写笔记不需要改插件。不要因为不熟悉就删除 `LegacyAnchors` 或 `LegacyRoutes`；它们承担历史链接兼容。

## 12. 旧网址兼容：哪些可以保留，哪些不会自动保留

普通文章当前以 `.html` 为规范网址，例如：

```text
当前文章：/quartz-site/Rust/所有权.html
原站路径：/quartz-site/Rust/所有权/
```

迁移文章的旧目录路径会通过兼容页跳转到当前文章，并保留查询参数和标题锚点。旧标题锚点由 `LegacyAnchors` 补充，新的 Quartz 锚点也能使用。原首页旧标题会转到“关于本站”对应位置。

但是：

- `/quartz-site/` 下的旧文章路径兼容，不代表过去的 `/mkdocs-site/` 项目前缀也会自动跳转。
- GitHub 仓库更名，不会自动为所有旧 Pages 路径提供转发。
- 新文章不需要添加到迁移清单；迁移清单不是当前全部文章的总目录。
- `scripts/migrate_mkdocs.py` 是首次迁移工具，不是更新站点命令；日常不要重跑。

需要恢复或修改迁移逻辑时，先读 `migration/迁移说明.md`，并保留原文、旧新路径映射和备份。

## 13. 改完之后，怎样验证

### 13.1 标准三步

```bash
npm run check
npm run build
npm run validate
```

按顺序运行，前一步失败就先处理，不要把旧产物的验证成功当作本次修改成功。

| 命令 | 能发现什么 | 不能替代什么 |
| --- | --- | --- |
| `npm run check` | TypeScript 配置或组件的类型问题 | 不检查笔记内容正确性，也不检查视觉效果 |
| `npm run build` | Markdown / 配置 / 资源能否生成网站 | 不保证每个链接都正确，也不保证好看 |
| `npm run validate` | 输出中的本地引用、锚点、旧内容覆盖、旧路径、字体和正式网址等回归 | 不逐一访问外部网站，不代替浏览器交互检查 |

`validate` 默认检查 `public/`。如需额外检查已经构建的预览目录：

```bash
npm run validate -- --output .preview
```

预览目录验证不能代替正式构建验证；某些正式网址和索引要求只在 `public/` 验收时检查。

修改 TypeScript 逻辑时，还可以运行单元测试：

```bash
npm test
```

### 13.2 浏览器检查清单

构建并启动本机预览后，至少检查：

- [ ] 首页能打开，顶部菜单、搜索和主要按钮正常。
- [ ] 新文章可以从侧栏找到，搜索标题也能找到。
- [ ] 文章中的站内链接、图片、代码块和提示块正常。
- [ ] 分类页内容合理，手写链接没有遗漏或过时。
- [ ] 关系图节点可以点击，新加的站内链接产生合理关联。
- [ ] 用浏览器缩窄到手机宽度，导航、代码和表格没有把整页撑坏。
- [ ] 如果改了外观，打开排版预览并检查长段落、中文、代码注释。
- [ ] 如果改了兼容或文件位置，旧网址与旧标题链接仍能访问。

仓库还有首页浏览器回归脚本，需要本机已有 `agent-browser`，并先启动预览：

```bash
node scripts/verify_homepage.mjs
node scripts/verify_home_graph.mjs http://localhost:8082/quartz-site/
```

这不是部署命令，也不是写一篇普通笔记必须安装的额外工具。截图输出在被 Git 忽略的 `artifacts/` 中。

## 14. 从本机修改到正式发布

### 14.1 当前发布机制

```text
本地编辑 → 检查与预览 → git commit → git push 到 main
                                            ↓
                                  GitHub Actions 自动运行
                                            ↓
                                安装依赖 → 类型检查
                                            ↓
                                  构建 → 静态验证
                                            ↓
                                public/ 发布到 gh-pages
                                            ↓
                                    GitHub Pages 展示
```

对应配置：`.github/workflows/publish.yml`。当前工作流在推送 `main` 时触发，也支持在 GitHub Actions 页面手动触发。它使用 Node.js 22，发布至已有 `gh-pages` 分支。

GitHub 仓库 Settings → Pages 应沿用 **Deploy from a branch** 的分支发布方式，分支为 `gh-pages`，目录为根目录 `/`。不要仅因为源码中存在 Actions 工作流，就擅自把 Pages 来源切换成另一套发布模式。

### 14.2 发布前确认自己提交了什么

先查看当前分支和改动：

```bash
git branch --show-current
git status --short
git diff --stat
git diff
```

注意：`git diff` 默认不显示未跟踪文件的内容；新增文章要在编辑器中打开检查。已有暂存内容还要用 `git diff --cached` 查看。

如果当前不是 `main`，不要在有未保存工作时随意切分支；先明确分支的合并方式。不要用 `git add .` 盲目把他人的修改、私人资料或实验文件全部加入。

下面是**未来确认发布本文时**可参考的一组命令，只有这些确实是本次想提交的文件时才执行：

```bash
git add -- content/网站配置与使用指南.md content/笔记导航.md README.md
git diff --cached --stat
git diff --cached
```

确认暂存区里没有无关或敏感文件，再执行：

```bash
git commit -m "添加网站配置与使用指南"
```

`commit` 完成后仍只在本机。**下面的命令会把 `main` 分支推到远程并触发上线**，只有你确实要发布、且已确认当前分支与待推送提交时才执行：

```bash
git push origin main
```

如果此前已暂存其他文件，它们也会进入同一次提交，不能只看本次 `git add` 的几个路径。推送还可能带上本地尚未发布的其他提交，执行前应一并确认。

### 14.3 怎样确认线上真的更新了

1. 打开仓库的 Actions 页面，找到本次提交对应的“构建并发布笔记网站”。
2. 确认安装、检查、构建、验证、发布各步骤成功；失败时看第一处错误。
3. 检查 Pages 的发布记录，再打开正式网站的新文章地址。
4. 强制刷新，核对本次修改的文字或功能，而不只是确认首页能打开。

工作流成功不等于你已经人工验收线上页面。不要把“本地构建通过”写成“线上已发布成功”。

## 15. 改错了怎样撤销：先保护当前内容

### 15.1 局部修改的最安全习惯

每次只做一个目标，例如先改字号，再改首页卡片，不要把依赖升级、文章搬迁和样式重做混在一次修改里。

开始前：

```bash
git status --short
git diff -- quartz.config.ts quartz.layout.ts
```

Git **不会自动保护尚未提交的修改、未跟踪文件和被忽略的文件**。如果准备改配置，而文件里已经有重要的未提交内容，先单独备份。

例如备份当前主配置与布局到仓库外；这只是需要时手动执行的示例：

```bash
backup="$HOME/workspace/backups/quartz-site/$(date +%Y%m%d-%H%M%S-%N)--config-edit"
mkdir -p "$backup"
cp -- quartz.config.ts quartz.layout.ts "$backup/"
cmp -- quartz.config.ts "$backup/quartz.config.ts"
cmp -- quartz.layout.ts "$backup/quartz.layout.ts"
printf '备份位置：%s\n' "$backup"
```

`cmp` 成功时通常没有输出。要改首页，还应备份首页组件、首页样式和 `content/index.md`；要改其他文件，按实际范围增加，而不是假定上面的两个文件足够。

大范围变更应在同一备份目录写一份 README，记录时间、目的、原路径、已备份文件、验证结果和恢复方法；不要把令牌等凭据写进去。不要覆盖旧备份。

### 15.2 根据情况选择撤销方式

| 情况 | 更稳妥的办法 |
| --- | --- |
| 刚在编辑器中改错几行 | 用撤销，或者对照差异恢复这几行 |
| 改动尚未提交，但原来就有其他未提交修改 | 只撤销本次改动；不要整文件恢复到 Git 版本 |
| 有本次修改前的文件备份 | 核对备份版本、后续修改后再恢复对应文件 |
| 已有独立提交，但尚未 / 已经发布 | 阅读差异后考虑 `git revert` 创建反向提交，不重写历史 |
| 生成物不对，但源文件是正确的 | 重新构建，无需手改生成网页 |

不要把 `git reset --hard`、`git clean -fd` 当作普通修复命令：它们可能丢弃工作区或未跟踪文件。即使 `git restore 某文件` 也可能覆盖该文件中别的未提交内容。

从备份恢复前，停止正在重建网站的进程，核对原文件是否已有后续修改；恢复后重新执行检查、构建、验证和预览。不要为了“试一试回退是否有效”直接操作线上版本。

### 15.3 撤销本次指南本身

本次指南只新增 `content/网站配置与使用指南.md`，并在 `content/笔记导航.md` 和 `README.md` 各增加入口；没有改变网站配置或发布流程。若以后不需要，先确认没有新增引用或后续编辑，再移除指南及这两个入口并重新构建验证；不要整文件回退，避免覆盖其他笔记维护内容。

## 16. 常见问题：先找原因，再动手

| 现象 | 优先检查 | 不要先做什么 |
| --- | --- | --- |
| 保存后网页没变 | 是否重建 `.preview/`，是否等构建结束再刷新 | 不要先重装依赖 |
| 正式构建通过，但本地还是旧内容 | `npm run build` 写入 `public/`，预览读取 `.preview/` | 不要直接修改预览 HTML |
| 预览打不开 | 终端是否显示就绪、端口是否正确、路径是否含 `/quartz-site/` | 不要先改正式域名 |
| 报端口占用 | 换用 `PORT=8083 npm run serve` | 不要结束不认识的系统进程 |
| 新文章找不到 | 文件是否在 `content/`、扩展名是否 `.md`、是否为草稿或被忽略、是否重新构建 | 不要以为必须先注册到 JSON |
| 新文章没出现在首页最近记录 | 是否位于 `随记/`，`created` 是否正确，是否进入前两篇 | 不要改全站日期规则碰运气 |
| 关系图有点没有线 | 是否真的写了指向其他文章的站内链接 | 标签相同不一定会自动连线 |
| 链接 / 图片 404 | 路径是否从内容库根开始、大小写是否一致、文件是否实际存在 | 不要加入本机绝对路径 |
| 文章没有右侧目录 | 是否至少有两个范围内标题、是否关闭目录、是否在手机宽度 | 不要立刻改框架代码 |
| 修改主题色无效 | 是否被正文或首页 SCSS 的固定色值覆盖 | 不要批量替换所有颜色 |
| 中文新字显示异常 | 字体资源请求是否成功、浏览器字体加载是否报错 | 不要先重新生成全部字体 |
| `npm ci` 因版本失败 | Node / npm 是否符合要求，锁文件是否与依赖一致 | 不要随意删除锁文件或用 `sudo npm` |
| `sharp` 尝试源码编译 | 是否按说明设置了 `SHARP_IGNORE_GLOBAL_LIBVIPS=1` | 不要先修改系统 libvips |
| `check` 失败 | 输出中的第一个文件和行号，最近是否破坏括号或字段类型 | 不要忽略错误继续发布 |
| `build` 失败 | 第一个错误，YAML 格式、代码围栏、组件语法、资源引用 | 不要只看日志最后一句 |
| `validate` 报错 | 错误给出的具体页面、资源、锚点或校验项 | 不要通过删验收规则来掩盖错误 |
| 本地通过但线上没变 | 是否已推送 `main`、Actions 是否成功、Pages 是否完成、缓存是否过期 | 不要把本地成功当线上成功 |
| 生产验证提示分享 / RSS 网址错误 | `baseUrl` 是否被环境变量覆盖，项目路径是否一致 | 不要把 localhost 当正式地址 |

排错时先记下：执行的命令、第一处错误、最近改了哪些文件、预期与实际差异。一次只验证一个原因，能显著减少反复试错。

## 17. 不建议日常随手执行的操作

- `npm run format`：当前命令会格式化整个仓库，容易引入大量无关差异；只调整排版时应指定目标文件。
- 旧教程中的 `mkdocs build`：本站已经不靠 MkDocs 构建。
- Quartz 的整站初始化、上游同步或自动推送命令：可能覆盖当前定制或改变 Git 状态；本站日常使用本文的 npm 命令即可。
- `npm update`、`npm audit fix --force`：会改变依赖，不是修复文章排版的工具。
- 重新运行 `scripts/migrate_mkdocs.py`：这是历史迁移工具，不是同步笔记工具。
- 删除 `migration/`、替换整个 `quartz/`、批量重命名原站文章：会影响长期兼容与恢复能力。
- 把 `.env`、私人备份、密钥或本地 AI 运行记录提交到公开仓库。

依赖升级应作为独立任务：确认改动范围、备份未提交工作、审查锁文件差异，并完整运行测试、构建、静态验收和浏览器检查。

## 18. 最后保留一张操作速查表

| 想做什么 | 先打开 / 先运行 |
| --- | --- |
| 写文章 | `content/对应分类/文章名.md` |
| 加图片 | `content/assets/` 下放附件，再在笔记中引用 |
| 修改分类介绍 | `content/对应分类/index.md` |
| 修改“学习笔记”入口 | `content/笔记导航.md` |
| 调整侧栏顺序 | `site.navigation.json` → `python3 scripts/build_navigation.py` |
| 改站名 | `quartz.config.ts` 的 `pageTitle` 与标题后缀 |
| 改首页大字、菜单、卡片 | `quartz/components/HybridHome.tsx`，同步摘要 |
| 改最近随记数量 | 首页组件的 `.slice(0, 2)` |
| 改正文外观 | `quartz/styles/custom.scss` |
| 改首页外观 | `quartz/components/styles/hybridHome.scss` |
| 改代码高亮颜色 | `quartz/util/previewTheme.ts` |
| 改布局或页脚 | `quartz.layout.ts` |
| 本地预览 | `npm run serve` |
| 确认能否发布 | `npm run check` → `npm run build` → `npm run validate`，再浏览器验收 |
| 正式上线 | 审查改动 → 提交 → 确认推送 `main` → 看 Actions / Pages → 线上核验 |
