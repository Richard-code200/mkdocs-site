## 一句话理解

> **Context 是模型当前能看到的信息，Prompt 是给模型的指令或输入，Skill 是可复用的办事方法。**

这里的 Agent 指围绕目标，利用模型选择行动、调用工具并根据结果继续工作的系统。模型负责理解和决策，宿主程序负责组织上下文、提供工具并执行调用；具体分工因实现而异。

| 概念 | 中文 | 核心问题 | 例子 |
| --- | --- | --- | --- |
| Context | 上下文 | 这一次模型能看到什么？ | 对话历史、项目说明、已读取的代码、测试报错 |
| Prompt | 提示词 | 要模型做什么，有什么要求？ | “检查这段代码，重点关注安全问题，用中文回答” |
| Skill | 技能 | 这类事情应该按什么方法做？ | 排查 bug 的步骤、代码审查清单、配套脚本与模板 |

它们不是三个互斥的盒子：**Prompt 通常是 Context 的一部分，Skill 被加载的内容也会进入 Context。**

## Context：模型当前可见的信息

Context 是模型在某一次调用中实际接收到的信息，通常包括：

- 系统和开发者指令：角色、行为规则、安全边界等。
- 用户请求，以及被保留的历史对话。
- 已注入或通过工具读取的项目说明、代码和资料。
- 工具定义，以及命令、搜索、测试等工具返回的结果。
- 已加载的技能说明、记忆摘要或检索片段。

### 文件存在，不等于模型已经看见

仓库里有 `README.md`、磁盘上安装了某个 Skill，并不代表模型已经读取它们。通常要由宿主注入，或通过工具读取，内容才会进入上下文。

同样，工具读取结果如果被截断，模型看到的也只是返回的部分。

### 上下文不等于永久记忆

模型有上下文窗口限制，通常以 token 衡量。对话变长后，Agent 系统可能删减、摘要或重新检索历史内容，因此不能假设模型始终记得之前的每一句话。

即使某个 Agent 提供长期记忆，相关记忆通常也需要被检索或注入，才能用于当前回答。模型训练形成的知识则属于模型参数，不等同于当前上下文。

> [!info] 上下文管理的目标
> 不是把所有资料一次性塞进去，而是让当前任务所需的信息准确、相关、足够，并尽量减少过期信息和噪声。

## Prompts：目标、要求与输入

Prompt 常被译为“提示词”，但并不限于几个关键词，可以是一句话、一段说明，也可以是结构化消息。

日常讨论时，人们常用 Prompt 指给模型的任务指令；在更宽泛的技术语境中，也可能用它指一次调用的整体输入。因此讨论时最好先明确所指范围。

### 常见内容

- **目标**：需要解决什么问题。
- **背景**：为什么做，当前条件是什么。
- **约束**：哪些事情可以做、不能做。
- **输出要求**：语言、结构、篇幅与格式。
- **验收标准**：怎样判断任务完成。

例如：

```text
请检查 src/login.ts 中的登录逻辑。
重点关注身份验证和错误处理，不修改代码。
用中文列出问题、影响和对应位置；没有足够证据时说明不确定性。
```

### Prompt 模板是什么

Prompt 模板是可重复使用、带有可替换部分的提示词，例如：

```text
请审查以下代码：
{{code}}

重点关注：{{focus}}
输出格式：问题、证据、建议。
```

模板填入实际内容并发送给模型后，才成为当前调用的输入。它可以是独立文件，也可以被某个 Skill 或应用使用。

## Skills：可复用的任务方法

在许多编码 Agent 中，Skill 是围绕一类任务组织的说明与资源，告诉 Agent 应在什么时候使用、按什么步骤执行，以及如何验证结果。

一个 Skill 可能包含：

- 适用场景和触发条件。
- 操作步骤、检查清单与注意事项。
- 需要调用的工具或命令示例。
- 配套脚本、模板、参考文档。

一种常见的目录形式是：

```text
example-skill/
├── SKILL.md
├── scripts/
├── references/
└── templates/
```

这只是示意，并非所有平台的强制标准，也不是每个 Skill 都有这些目录。

### Skill 与 Prompt 模板的区别

Prompt 模板通常复用一段输入的表达结构；Skill 更侧重封装一类任务的执行方法，可能包含多步骤流程、检查清单和辅助资源。

两者没有绝对边界：简单 Skill 可能只有一份说明，也可以在执行过程中使用 Prompt 模板。

### Skill 与 Tool 的区别

- **Skill 说明怎么做**：例如先复现 bug，再定位根因，最后验证修复。
- **Tool 提供执行动作的接口**：例如读取文件、运行测试、操作浏览器。

Skill 本身不等于模型重新训练，也不会自动赋予系统权限。即使技能要求运行某个命令，Agent 仍需要可用的工具、依赖和相应授权。

> [!warning] 安装不等于启用，启用不等于可靠执行
> 不同 Agent 的技能发现、加载和执行机制不同。不能仅凭“装了这个 Skill”就认定模型已经读取内容，或一定会正确遵循。

## 三者如何协作

以“修复项目中的一个 bug”为例：

```text
用户用 Prompt 提出任务
        ↓
Agent 发现并加载适用的调试 Skill
        ↓
Agent 按步骤调用工具，读取代码、复现问题
        ↓
技能说明、代码和工具结果进入或更新 Context
        ↓
模型根据当前 Context 决定下一步
        ↓
继续执行、验证，或向用户澄清
```

这是一个简化示意：实际调用顺序、是否自动加载技能，以及保留多少历史信息，都取决于具体 Agent 的实现。

以 `using-superpowers` 为例：它作为可复用的方法说明属于 **Skill**；说明内容被加载后成为 **Context** 的一部分；其中“先检查适用技能”等要求则发挥 **Prompt 指令**的作用。

## 用做菜来类比

- **Context**：有哪些食材、几个人吃、有没有忌口。
- **Prompt**：今晚做两道清淡的菜，半小时内完成。
- **Skill**：一套菜谱和烹饪方法。
- **Tool**：刀、锅和炉灶，提供实际操作能力。

类比只能帮助记忆：Agent 能否真正执行动作，还取决于宿主程序提供的工具与权限。

## 常见误区速查

| 误区 | 更准确的理解 |
| --- | --- |
| Context 就是聊天记录 | 聊天记录只是其中一部分，还可能包括指令、工具结果和外部资料 |
| Prompt 只能是用户发的一句话 | 系统、开发者或应用也会组织指令；宽泛意义上可指整体输入 |
| 文件在项目里，模型就知道内容 | 需要实际读取或注入，而且要留意截断和摘要 |
| 装了 Skill 就提升了模型本身的智力 | 通常是提供更好的流程和资源，不改变模型参数 |
| Skill 就是一个工具 | Skill 主要描述方法，Tool 提供动作接口；二者可以配合 |
| Skill 写了“必须”，就有更高权限 | 文档措辞不改变实际指令层级、系统权限或用户授权 |
| 上下文越多越好 | 相关性、准确性和组织方式同样重要，无关信息可能干扰判断 |

## 如何选择该改什么

- **模型不知道必要事实**：补充或检索相关 Context。
- **模型不清楚目标、边界或输出形式**：改进 Prompt。
- **同一类任务总是漏步骤、反复解释方法**：考虑整理为 Skill。
- **模型知道怎么做，但无法执行动作**：检查 Tool、依赖与权限，而不只是继续改提示词。

这些是排查方向，不是绝对归因；实际问题可能同时涉及多个环节。
