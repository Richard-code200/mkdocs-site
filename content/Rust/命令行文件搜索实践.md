通过 minigrep 练习参数解析、借用、迭代器、自定义错误和测试，以下按当前实现记录。项目使用 edition 2024，暂不依赖第三方 crate，也没有使用 clap。

## 职责分工

```text
minigrep/
├── Cargo.toml
├── poem.txt
├── src/
│   ├── main.rs    # 取得参数,报告错误,设置失败退出码
│   └── lib.rs     # Config、ConfigError、读取文件、搜索、单元测试
└── tests/
    └── cli.rs     # 启动真实二进制的集成测试
```

main.rs 与 lib.rs 属于同一 Package 的不同 crate.main 通过 `minigrep::Config` 和 `minigrep::run` 使用库的公开 API;Config 的类型、构建方法和需要在外部访问的字段必须分别处理可见性.详见[项目代码组织](Rust/项目代码组织.md).

## 先明确命令的行为契约

命令形式:

```text
minigrep <query> <file_path>
```

| 情况 | 当前约定 |
| ---- | -------- |
| 缺少查询参数 | `ConfigError::MissingQuery` |
| 查询词是空字符串 | 合法,匹配 lines 产生的所有行 |
| 缺少路径参数 | `ConfigError::MissingFilePath` |
| 提供路径但字符串为空 | `ConfigError::EmptyFilePath` |
| 提供多余参数 | `ConfigError::TooManyArguments` |
| 路径存在但文件读取失败,或路径不存在 | 运行阶段报告读取错误,不是参数缺失 |
| 没有匹配行 | 正常成功退出,stdout 为空 |

不要对文件路径调用 trim 再判断:空格可能是合法文件名的一部分.同样,搜索结果应保留原文大小写、空格和顺序.

### 直接消费参数迭代器

Config 保存 `query: String`、`file_path: String` 和两个 bool 开关.在其 impl 中,构建方法接收迭代器:

```rust
// 位于 impl Config 中;ConfigError 的定义见错误处理笔记
pub fn build(mut args: impl Iterator<Item = String>) -> Result<Config, ConfigError> {
    args.next(); // 第一项是程序路径,不是查询词
    let query = args.next().ok_or(ConfigError::MissingQuery)?;
    let file_path = args.next().ok_or(ConfigError::MissingFilePath)?;

    if file_path.is_empty() {
        return Err(ConfigError::EmptyFilePath);
    }
    if args.next().is_some() {
        return Err(ConfigError::TooManyArguments);
    }

    Ok(Self {
        query,
        file_path,
        ignore_case: std::env::var("IGNORE_CASE").is_ok(),
        show_line_numbers: std::env::var("SHOW_LINE_NUMBERS").is_ok(),
    })
}
```

示例按当前行为整理，源码中读取环境开关的位置无需调整。通过 next 取得 String 后直接放入 Config,不必先 collect 成 Vec 再 clone.缺少参数时 ok_or 把 Option 变成 Result,`?` 提前返回.完整错误类型与转换说明见[错误处理](Rust/错误处理.md).

## 环境变量开关:检查存在性,不解析布尔值

```rust
let ignore_case = std::env::var("IGNORE_CASE").is_ok();
let show_line_numbers = std::env::var("SHOW_LINE_NUMBERS").is_ok();
```

这里的规则是“存在且可读为 Unicode 字符串就开启”,不是把文本解析为 true/false.因此值为 `"0"`、`"false"` 或空字符串也会开启;未设置或 var 读取失败时关闭.

在项目根目录的 shell 中运行:

```bash
# 明确移除两个外部开关,按默认规则搜索
env -u IGNORE_CASE -u SHOW_LINE_NUMBERS cargo run -- nobody poem.txt

# 忽略大小写并显示原文件行号
IGNORE_CASE=1 SHOW_LINE_NUMBERS=1 cargo run -- NOBODY poem.txt
```

`cargo run --` 后面的内容交给程序作为参数.当前 poem.txt 中 nobody 的匹配行在第 1、3 行,行号输出形式为:

```text
1:I'm nobody! Who are you?
3:Are you nobody, too?
```

| IGNORE_CASE | SHOW_LINE_NUMBERS | 输出行为 |
| ----------- | ----------------- | -------- |
| 关闭 | 关闭 | 区分大小写,只输出原文 |
| 开启 | 关闭 | 忽略大小写,只输出原文 |
| 关闭 | 开启 | 区分大小写,输出 行号:原文 |
| 开启 | 开启 | 忽略大小写,输出 行号:原文 |

四种组合都有 CLI 集成测试覆盖.测试通过 Command.env/env_remove 控制子进程环境,不修改测试进程的全局环境,见[测试](Rust/测试.md).

## 读取与搜索:返回原文切片

当前 run 用 `std::fs::read_to_string` 一次读取完整文件,根据两个开关选择搜索函数,最后打印匹配结果:

| 搜索函数 | 返回类型 |
| -------- | -------- |
| `search` | `Vec<&str>` |
| `search_case_insensitive` | `Vec<&str>` |
| `search_with_line_numbers` | `Vec<(usize, &str)>` |
| `search_case_insensitive_with_line_numbers` | `Vec<(usize, &str)>` |

这些签名省略了表格中的生命周期,实际返回的 `&str` 都借自 contents.当前 Vec 会分配保存结果的空间,忽略大小写还会创建临时小写 String,所以“不复制每行原文”不等于“整个过程零分配”.

行号必须先 enumerate 再 filter,否则编号会变成匹配结果的序号.具体实现见[迭代器与闭包](Rust/迭代器与闭包.md);返回值只关联 contents、不关联 query 的原因见[生命周期](Rust/生命周期.md).

## 入口决定如何报告错误

```rust
// src/main.rs
use minigrep::Config;
use std::{env, process};

fn main() {
    let config = Config::build(env::args()).unwrap_or_else(|err| {
        eprintln!("Problem parsing arguments: {err}");
        process::exit(1)
    });

    if let Err(err) = minigrep::run(config) {
        eprintln!("Application error: {err}");
        process::exit(1)
    }
}
```

- 参数错误使用稳定前缀 `Problem parsing arguments:`,运行错误使用 `Application error:`.
- 错误写 stderr,失败退出码是 1;stdout 只保留匹配结果,不混入 Searching for/In file 等提示.
- `{err}` 使用 Display,不是 Debug;底层 `?` 只传播错误,不会自动调用 eprintln 或 process::exit.
- Config::build 返回具体的 ConfigError,run 当前返回 `Result<(), Box<dyn std::error::Error>>`,两者不必使用相同的错误类型.
