Rust 将错误分为两大类:**可恢复错误**(Recoverable)和**不可恢复错误**(Unrecoverable).

| 类型 | 表示方式 | 场景 |
| ---- | -------- | ---- |
| 可恢复错误 | `Result<T, E>` | 文件不存在、网络超时等可以重试的情况 |
| 不可恢复错误 | `panic!` 宏 | 数组越界、逻辑错误等程序无法继续的情况 |

## panic! -- 不可恢复错误

`panic!` 会立即终止程序,打印错误信息并展开调用栈:

```rust
fn main() {
    panic!("程序崩溃了!");
}
```

```bash
thread 'main' panicked at '程序崩溃了!', src/main.rs:2:5
```

常见触发场景:

```rust
let v = vec![1, 2, 3];
v[99]; // panic: index out of bounds
```


> [!info] panic 的两种策略
> Rust 默认在 panic 时**展开**(unwind)调用栈,逐层清理数据.也可以在 `Cargo.toml` 中设置为**中止**(abort),直接退出程序:
> 
> ```toml
> [profile.release]
> panic = 'abort'
> ```
> 


## `Result<T, E>` -- 可恢复错误

`Result` 是 Rust 错误处理的核心,定义在标准库中:

```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

- `Ok(T)`:操作成功,包含返回值
- `Err(E)`:操作失败,包含错误信息

### 基本用法

```rust
use std::fs::File;

fn main() {
    let greeting_file_result = File::open("hello.txt");

    let greeting_file = match greeting_file_result {
        Ok(file) => file,
        Err(error) => panic!("打开文件失败: {error:?}"),
    };
}
```

### 匹配不同的错误类型

```rust
use std::fs::File;
use std::io::ErrorKind;

fn main() {
    let greeting_file = match File::open("hello.txt") {
        Ok(file) => file,
        Err(error) => match error.kind() {
            ErrorKind::NotFound => match File::create("hello.txt") {
                Ok(fc) => fc,
                Err(e) => panic!("创建文件也失败了: {e:?}"),
            },
            other_error => panic!("打开文件失败: {other_error:?}"),
        },
    };
}
```


> [!info] 闭包简化写法
> 上面的嵌套 match 可以用闭包和方法链简化:
> 
> ```rust
> let greeting_file = File::open("hello.txt").unwrap_or_else(|error| {
>     if error.kind() == ErrorKind::NotFound {
>         File::create("hello.txt").unwrap_or_else(|error| {
>             panic!("创建文件也失败了: {error:?}");
>         })
>     } else {
>         panic!("打开文件失败: {error:?}");
>     }
> });
> ```
> 


## 快捷方式

### unwrap -- 成功就返回值,失败就 panic

```rust
let greeting_file = File::open("hello.txt").unwrap();
// 如果 Ok,返回文件;如果 Err,调用 panic!
```

### expect -- 带自定义信息的 panic

```rust
let greeting_file = File::open("hello.txt")
    .expect("hello.txt 应该存在于项目中");
// 和 unwrap 类似,但 panic 信息更友好
```


> [!warning] unwrap 和 expect 的使用场景
> `unwrap` 和 `expect` 适用于**确定不会失败**的场景(如测试、原型).生产代码中应优先使用 `match` 或 `?` 运算符进行完整的错误处理.


### unwrap 家族

| 方法 | 成功时 | 失败时 |
| ---- | ------ | ------ |
| `unwrap()` | 返回 `T` | panic |
| `expect("msg")` | 返回 `T` | panic 并附带信息 |
| `unwrap_or(default)` | 返回 `T` | 返回默认值 |
| `unwrap_or_else(\|e\| ...)` | 返回 `T` | 执行闭包 |
| `unwrap_or_default()` | 返回 `T` | 返回 `T::default()` |

## ? 运算符 -- 错误传播

`?` 是错误传播的语法糖,让错误处理代码更简洁:

```rust
use std::fs::File;
use std::io::{self, Read};

fn read_username_from_file() -> Result<String, io::Error> {
    let mut username_file = File::open("hello.txt")?;
    // 如果 File::open 返回 Err,? 会立即将 Err 从函数返回
    // 如果返回 Ok,将文件赋给 username_file

    let mut username = String::new();
    username_file.read_to_string(&mut username)?;
    // 同理,read_to_string 失败时也会传播错误

    Ok(username)
}
```


> [!info] ? 运算符的展开形式
> `?` 运算符等价于以下 match 表达式:
> 
> ```rust
> let username_file = match File::open("hello.txt") {
>     Ok(file) => file,
>     Err(e) => return Err(e.into()),
> };
> ```
> 
> 对这里的 `Result` 错误传播,`?` 通过 `From` 转换错误类型:如果原始错误类型是 `E1`,函数返回 `Result<T, E2>`,就需要目标类型满足 `E2: From<E1>`.转换方向是**操作产生的错误 → 当前函数要求的错误**.目标与来源类型相同时也可以使用 `?`.
> 
> `?` 不会自动打印错误,也不会直接退出整个程序;它提前返回的是**当前函数**.


### 链式调用

`?` 可以链式调用,让代码非常简洁:

```rust
fn read_username_from_file() -> Result<String, io::Error> {
    let mut username = String::new();
    File::open("hello.txt")?.read_to_string(&mut username)?;
    Ok(username)
}
```

更简洁的写法 -- 直接用标准库函数:

```rust
fn read_username_from_file() -> Result<String, io::Error> {
    std::fs::read_to_string("hello.txt")
}
```

### 使用 ? 要匹配函数的返回类型

在上面的文件读取例子中,`?` 需要所在函数返回兼容的 `Result`.它不能直接用于默认返回 `()` 的 `main`.另外,返回 `Option` 的函数也可以对 `Option` 使用 `?`,但不能不经转换就把 `Option` 和 `Result` 混用.

```rust
fn main() {
    let greeting_file = File::open("hello.txt")?;
    // 编译错误:the `?` operator can only be used in a function
    // that returns `Result`
}
```

`main` 函数可以改为返回 `Result`:

```rust
use std::error::Error;
use std::fs::File;

fn main() -> Result<(), Box<dyn Error>> {
    let greeting_file = File::open("hello.txt")?;
    Ok(())
}
```


> [!info] Box<dyn Error>
> `dyn Error` 是 trait 对象类型,`Box<dyn Error>` 通过拥有型指针持有某个实现 `Error` 的具体错误,每次仍只装一个错误.它让函数可以用同一个返回类型传播不同来源的错误,无需先定义统一的错误枚举.
> 
> 这里省略的 trait 对象生命周期默认为 `'static`:所装的错误不能包含不满足该约束的短期借用.这不表示错误值一定存活到程序结束.当前项目的 `ConfigError` 和 `std::io::Error` 都满足要求.更多区别见[泛型与特征](Rust/泛型与特征.md).


## 实战示例:猜数游戏中的错误处理

猜数游戏中同时展示了 `expect` 和 `match` 两种错误处理方式:

```rust
let mut guess = String::new();

std::io::stdin()
    .read_line(&mut guess)
    .expect("读取输入失败");

let guess: u32 = match guess.trim().parse() {
    Ok(num) => num,
    Err(_) => continue,
};
```

- `expect`:对 `read_line` 的 `Result` 使用,失败时 panic 并显示提示信息
- `match + Err(_) => continue`:对 `parse` 的 `Result` 使用,输入非数字时跳过本次循环而非崩溃


> [!important] 错误处理策略选择
> 
> | 场景 | 推荐方式 |
> | ---- | -------- |
> | 原型 / 测试 | `unwrap()` / `expect()` |
> | 确定能恢复的错误 | `match` + 具体处理 |
> | 向上传播错误 | `?` 运算符 |
> | 用户输入验证 | `match` + `continue` / 默认值 |
> | 库函数 | 返回 `Result`,让调用者决定 |


## 自定义错误类型

当标准库的错误类型不够用时,可以定义自己的错误:

```rust
use std::fmt;

#[derive(Debug)]
enum MyError {
    NotFound(String),
    ParseError(String),
    Unknown,
}

impl fmt::Display for MyError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            MyError::NotFound(msg) => write!(f, "未找到: {msg}"),
            MyError::ParseError(msg) => write!(f, "解析失败: {msg}"),
            MyError::Unknown => write!(f, "未知错误"),
        }
    }
}

impl std::error::Error for MyError {}
```

### minigrep:用枚举区分参数错误

错误值与显示消息是两回事.枚举表达**是哪种错误**,`Display` 决定**如何向用户描述**:

```rust
use std::fmt;

#[derive(Debug, PartialEq, Eq)]
pub enum ConfigError {
    MissingQuery,
    MissingFilePath,
    EmptyFilePath,
    TooManyArguments,
}

impl fmt::Display for ConfigError {
    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
        let message = match self {
            ConfigError::MissingQuery => "missing query",
            ConfigError::MissingFilePath => "missing file path",
            ConfigError::EmptyFilePath => "file path must not be empty",
            ConfigError::TooManyArguments => "too many arguments",
        };
        write!(f, "{message}")
    }
}

impl std::error::Error for ConfigError {}
```

- `Debug` 支持 `{:?}`;`PartialEq` 支持比较错误变体;`Eq` 表示满足等价关系,包括自反性,不是“比较时用的函数”.
- `match self` 每次只选择一个匹配分支,不是遍历.明确写出四个变体,新增变体时编译器就会提醒更新消息映射.
- `write!` 将消息写入 `Formatter`,返回 `fmt::Result`.末尾没有分号,这个结果就是 `fmt` 的返回值;它不是返回一个 `String`.
- 实现 `Display` 后,`error.to_string()` 会按这个显示规则生成 `String`,不必再手写 `ToString`.

`Error` 要求类型已经实现 `Debug` 和 `Display`.其方法都有默认实现;这里没有底层错误来源,可以使用空实现块,默认的 `source()` 返回 `None`.


> [!important] Error 不等于打印、退出或 Result 的准入条件
> `Result<T, E>` 对 `E` 没有“必须实现 Error”的要求,所以尚未实现 Error 时,`Result<Config, ConfigError>` 就已经合法.
> 
> 实现 Error 是让类型符合标准错误接口;它不会自动打印消息或退出进程.这些动作由调用方决定.


### 从 Option 得到具体的参数错误

迭代器的 `next()` 返回 `Option<String>`,而参数构建函数返回 `Result<Config, ConfigError>`.可以先用 `ok_or` 转换:

```rust
// 位于 Config::build 内,省略其他参数检查
let query = args.next().ok_or(ConfigError::MissingQuery)?;
```

| 原值 | ok_or 后 | 接 ? 的结果 |
| ---- | -------- | ----------- |
| `Some(query)` | `Ok(query)` | 取出查询词 |
| `None` | `Err(ConfigError::MissingQuery)` | 提前返回当前函数 |

空字符串 `Some(String::new())` 与没有参数 `None` 不同.项目允许空查询词,但对存在却为空的文件路径另行返回 `EmptyFilePath`.完整参数约定见[命令行文件搜索实践](Rust/命令行文件搜索实践.md).

### Error 接口与 From 转换不是一回事

```rust
fn read_text(path: &str) -> Result<String, Box<dyn std::error::Error>> {
    let contents = std::fs::read_to_string(path)?;
    Ok(contents)
}
```

读取失败时产生 `std::io::Error`,函数要求返回 `Box<dyn Error>`.标准库已有相应转换,因此 `?` 可以传播这个错误.

如果只把返回类型改成 `Result<String, ConfigError>`,就需要另一条规则:

```text
std::io::Error → ConfigError
对应:ConfigError: From<std::io::Error>
```

当前项目没有实现这条规则,所以文件读取的 `?` 不能在该签名下编译.两种类型都实现 Error,**不代表它们可以互相转换**.而且 ConfigError 目前只描述参数错误,编译器不能替我们决定如何把“文件权限不足”映射成其中某个变体.

显式练习已有的装箱转换:

```rust
let error: Box<dyn std::error::Error> = ConfigError::MissingQuery.into();
assert_eq!(error.to_string(), "missing query");
```

左侧标注告诉 `.into()` 目标类型是什么.标准库为这里满足约束的具体错误提供到 `Box<dyn Error>` 的 From 转换,因而可以调用 `.into()`.里面的具体错误仍然是 ConfigError,并没有变成文件读取错误.

相关测试见[测试](Rust/测试.md),`dyn` 的含义见[泛型与特征](Rust/泛型与特征.md).


> [!info] 错误处理的完整链路
> 实际项目中,通常使用 `thiserror` crate 简化自定义错误,用 `anyhow` crate 处理应用层错误.它们都基于 `std::error::Error` trait.



> [!important] 错误处理核心要义
> Rust 的错误处理机制强制你**显式**处理可能失败的操作.没有隐藏的异常,没有隐式的错误传播 —— 每个 `Result` 都必须被处理,这让程序更加健壮可靠.
