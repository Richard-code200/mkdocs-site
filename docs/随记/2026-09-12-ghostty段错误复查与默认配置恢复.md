# Ghostty 段错误复查与默认配置恢复

**日期**：2026-09-12

**环境**：Fedora 44、Wayland、niri、Ghostty 1.3.1-4.fc44

**前次记录**：[Ghostty 在 Fedora 43→44 升级后 Segmentation Fault 问题](ghostty-segfault-问题排查.md)

## 结论

在本机当前的软件版本和配置下，取消 `GLYCIN_DATA_DIR` 绕过、恢复系统默认 SVG 加载器的 `Fontconfig=true` 路径后，Ghostty 可以正常创建窗口、运行子进程并退出，未复现原来的启动段错误。

据此撤除了有效配置中的环境变量覆盖，并停用自定义 glycin loader 副本。系统加载器配置由 RPM 提供，不再手工修改。

这说明当前启动场景已不需要旧绕过方案，但不能仅凭本次测试确定历史故障究竟由哪个版本或补丁修复。原文保留为历史记录，当前处理方式以本文为准。

## 复查方法与结果

### 1. 核查系统加载器

检查文件：

```text
/usr/share/glycin-loaders/2+/conf.d/glycin-svg.conf
```

系统配置的两个 SVG 段落都已经包含 `Fontconfig=true`：

```ini
[loader:image/svg+xml]
Exec=/usr/libexec/glycin-loaders/2+/glycin-svg
ExposeBaseDir=true
Fontconfig=true

[loader:image/svg+xml-compressed]
Exec=/usr/libexec/glycin-loaders/2+/glycin-svg
ExposeBaseDir=true
Fontconfig=true
```

执行以下校验时无差异输出：

```sh
rpm -V glycin-loaders.x86_64 fontconfig.x86_64
```

这表明当前相关系统包文件与安装时的 RPM 记录一致，无需再覆盖 `/usr/share` 下的配置。

### 2. 修正 Fontconfig 的独立复现方法

前次记录中的 Python 代码没有声明 `ctypes` 函数签名：

```python
lib.FcConfigGetCacheDirs(lib.FcConfigGetCurrent())
```

`ctypes` 默认把函数返回值解释为 C `int`。但 `FcConfigGetCurrent()` 返回的是指针，在 64 位环境中可能被截断，导致后续调用使用无效地址。

因此，这段 Python 代码产生的段错误不能可靠地证明 Fontconfig 本身存在缺陷。它不否定历史上 Ghostty 的真实崩溃，只说明原文使用的这项独立证据不充分。

本次使用正确签名，并释放缓存目录迭代器：

```python
import ctypes
import ctypes.util

lib = ctypes.CDLL(ctypes.util.find_library("fontconfig"))
lib.FcInit.argtypes = []
lib.FcInit.restype = ctypes.c_int
lib.FcConfigGetCurrent.argtypes = []
lib.FcConfigGetCurrent.restype = ctypes.c_void_p
lib.FcConfigGetCacheDirs.argtypes = [ctypes.c_void_p]
lib.FcConfigGetCacheDirs.restype = ctypes.c_void_p
lib.FcStrListNext.argtypes = [ctypes.c_void_p]
lib.FcStrListNext.restype = ctypes.c_char_p
lib.FcStrListDone.argtypes = [ctypes.c_void_p]
lib.FcStrListDone.restype = None

assert lib.FcInit()
config = lib.FcConfigGetCurrent()
assert config

for _ in range(100):
    iterator = lib.FcConfigGetCacheDirs(config)
    assert iterator
    try:
        directories = []
        while value := lib.FcStrListNext(iterator):
            directories.append(value.decode())
    finally:
        lib.FcStrListDone(iterator)

print("连续调用 100 次成功：", directories)
```

结果：连续 100 次成功。缓存目录包括 `/usr/lib/fontconfig/cache`、`~/.cache/fontconfig` 和 `~/.fontconfig`。

### 4. 对照验证 Ghostty 窗口启动

每次测试均使用独立 Ghostty 进程，并显式设置：

```text
--gtk-single-instance=false
--quit-after-last-window-closed=true
--shell-integration=none
```

测试窗口直接启动 Python 子进程，记录其环境并在等待数秒后退出。通过 `niri msg --json windows` 检查窗口对应的 PID，确认新窗口真正出现。

不启动 Zsh，是为了避免 `.zshrc` 在测试过程中重新注入变量；关闭单实例复用，是为了避免请求被已有、仍带绕过环境的 Ghostty 进程接收。

| 场景 | 次数 | 结果 |
| --- | --- | --- |
| 旧绕过配置 | 1 | 窗口出现，子进程执行，退出码 0 |
| 取消绕过，使用系统默认加载器 | 3 | 全部正常，退出码均为 0，子进程中无 `GLYCIN_DATA_DIR` |

## 已执行的配置清理

### 删除环境覆盖

| 文件 | 删除内容 |
| --- | --- |
| `~/.zshrc` | `export GLYCIN_DATA_DIR="$HOME/.cache/glycin-data"` |
| `~/.config/niri/config.kdl` | `GLYCIN_DATA_DIR "/home/errorichard/.cache/glycin-data"` |
| `~/.config/environment.d/90-dms.conf` | `GLYCIN_DATA_DIR=/home/errorichard/.cache/glycin-data` |
| `~/.config/sway/scripts/environment.sh` | 同一变量的 `export` |
| `~/.config/sway/scripts/session.sh` | 向用户服务导入该变量的 `-E GLYCIN_DATA_DIR` 参数 |

历史 niri 备份目录中的旧配置作为备份保留；有效启动配置已经没有上述覆盖。

### 刷新 systemd 用户环境

仅执行 `unset-environment` 时，变量仍出现在用户管理器环境中。进一步检查发现，新的 environment.d 生成结果已不包含该变量，需要重新加载管理器来刷新生成环境：

```sh
systemctl --user daemon-reload
systemctl --user unset-environment GLYCIN_DATA_DIR
systemctl --user show-environment
```

刷新后确认输出中不再包含 `GLYCIN_DATA_DIR`。此操作不会让已经运行的应用自动清除其继承的环境变量。

### 停用自定义 loader，保留本次会话的过渡兼容

原来的 `~/.cache/glycin-data` 目录已移入：

```text
~/.local/state/ghostty-default-20260912/glycin-data/
```

原路径暂时替换为符号链接：

```text
~/.cache/glycin-data -> /usr/share
```

这样做的原因是：旧的桌面进程可能仍持有 `GLYCIN_DATA_DIR=~/.cache/glycin-data`。直接删除路径会导致它们找不到任何加载器，重新引入原文记录过的图像加载失败。

兼容链接使这些进程也读取 RPM 提供的默认 loader，包含 `Fontconfig=true`；不再使用任何修改过的 loader 副本。没有该变量的新进程则直接走系统默认发现路径。

## 当前会话与最后一步清理

在现有终端中清除继承值并重启 Shell：

```sh
unset GLYCIN_DATA_DIR
exec zsh
```

单纯 `exec zsh` 会继承旧变量，不能代替 `unset`。

完整注销并重新登录桌面会话后，检查：

```sh
printenv GLYCIN_DATA_DIR
systemctl --user show-environment
```

前者应无输出，后者不应包含该变量。确认后可删除本次会话的过渡链接：

```sh
if [ -L "$HOME/.cache/glycin-data" ] &&
   [ "$(readlink "$HOME/.cache/glycin-data")" = /usr/share ]; then
    unlink "$HOME/.cache/glycin-data"
fi
```

这里使用 `unlink` 删除链接本身，不操作 `/usr/share` 的内容。
