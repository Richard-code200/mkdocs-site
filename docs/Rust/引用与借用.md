# 引用与借用

## 什么是引用

**引用**(Reference)是 Rust 中一种不获取所有权的"借用"机制 -- 它允许你使用某个值,但不会让调用者失去对它的所有权.

```rust
let s1 = String::from("hello");
let s2 = &s1; // s2 是 s1 的引用,s1 仍然拥有该 String

println!("{s1}"); // 正常:s1 仍然有效
println!("{s2}"); // 正常:s2 借用了 s1
```

/// info | 引用 vs 所有权

|          | 所有权(Owner)          | 引用(&T)                  |
| -------- | ---------------------- | ------------------------- |
| 修改值   | 可以(如果是 mut)       | 默认不可变                |
| 释放内存 | 离开作用域时调用 drop  | 不负责释放                |
| 数量限制 | 同一时刻只有一个所有者 | 可同时存在多个不可变引用  |
| 消耗方式 | Move / Drop            | Copy(引用自身实现了 Copy) |

///

## 引用的基本语法

### 不可变引用 `&T`

```rust
let x = 42;
let r = &x;       // r 的类型是 &i32,读作"对 i32 的引用"

println!("x = {x}, r = {}", *r); // *r 解引用,获取原始值
```

### 可变引用 `&mut T`

```rust
let mut x = 42;
let r = &mut x;   // r 的类型是 &mut i32
*r += 1;          // 通过可变引用修改原值

println!("x = {x}"); // 43
```

/// important | 可变引用的前提
要创建可变引用,原始变量**必须声明为 `mut`**.不可变变量不能产生可变引用.
///

## 借用规则

Rust 借用检查器(Borrow Checker)强制执行两条铁律:

### 规则一:多个不可变引用可以共存

```rust
let s = String::from("hello");

let r1 = &s;
let r2 = &s;
let r3 = &s; // 任意多个不可变引用,完全合法

println!("{r1} {r2} {r3}");
```

### 规则二:不可变引用与可变引用不能同时存在

```rust
let mut s = String::from("hello");

let r1 = &s;       // 不可变借用
let r2 = &mut s;   // 编译错误:cannot borrow `s` as mutable because
                   // it is also borrowed as immutable
```

```rust
let mut s = String::from("hello");

let r1 = &mut s;   // 可变借用
let r2 = &mut s;   // 编译错误:同时存在两个可变借用
```

/// warning | 为什么要有这些限制
同时读写同一块内存是**数据竞争**(Data Race)的温床:

1. 两个或多个指针同时访问同一数据
2. 至少有一个指针在写入
3. 没有同步机制
   Rust 的借用规则在编译期**彻底消灭**了数据竞争.
   ///

### 借用规则的形式化表述

在任意给定时间,以下**二者只能选其一**:

- 任意多个不可变引用
- **恰好一个**可变引用

此外,所有引用**必须始终是有效的**(不能悬垂).

## 引用的作用域

引用从声明处开始,持续到**最后一次使用**:

```rust
let mut s = String::from("hello");

let r1 = &s;       // r1 的作用域开始
let r2 = &s;       // r2 的作用域开始
println!("{r1} {r2}"); // r1, r2 最后一次使用

// r1 和 r2 的作用域在此结束

let r3 = &mut s;   // 合法:之前的不可变借用已经结束
r3.push_str(", world!");
println!("{r3}");
// r3 的作用域在此结束
```

### 非词法作用域生命周期(NLL)

在 NLL(引入于 Rust 2018)之前,作用域以**代码块**为边界,上面的代码在 NLL 之前会编译失败.NLL 让编译器更精确地追踪引用的实际使用范围,减少了很多不必要的编译错误.

```rust
let mut s = String::from("hello");

let r1 = &s;
let r2 = &s;
// 如果这里是作用域边界(旧规则),以下代码会失败
// 但 NLL 允许,因为 r1, r2 在此之后不再使用

let r3 = &mut s; // NLL 下编译通过
```

/// info | NLL 的实际意义
NLL 让借用规则更智能,减少了大量"明明没冲突却编译不过"的情况.开发者在写代码时无需缩手缩脚,编译器会精确分析.
///

## 引用与函数

### 引用作为函数参数

```rust
fn calculate_length(s: &String) -> usize {
    s.len()
}

fn append_world(s: &mut String) {
    s.push_str(", world!");
}

fn main() {
    let mut s = String::from("hello");

    let len = calculate_length(&s); // 不可变借用
    println!("length: {len}");      // s 仍然可用

    append_world(&mut s);           // 可变借用
    println!("{s}");                // "hello, world!"
}
```

/// info | 函数签名即契约
通过参数类型就能判断函数的行为:

- `&T` :函数只会读取数据
- `&mut T`:函数可能会修改数据
- `T` :函数会获取所有权,调用方之后不能再使用该值
  ///

### 引用作为返回值

返回引用时,必须标注**生命周期**(Lifetime),告诉编译器返回的引用来自哪个参数:

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

生命周期注解 `'a` 表示返回的引用与参数 `x` 和 `y` 的生命周期相关联.

/// important | 生命周期是借用检查的核心
生命周期(lifetime)的话题将在后续笔记中详细展开.将其粗略理解为"引用有效的作用域范围".
///

## 悬垂引用(Dangling Reference)

悬垂引用是指向已释放内存的引用.Rust 编译器保证它**永远不会发生**:

```rust
fn dangle() -> &String {     // 预期返回 String 的引用
    let s = String::from("hello");
    &s                        // 返回引用...
}                             // ...但 s 在这里被释放!
// 编译错误:`s` does not live long enough
```

正确的做法是返回数据本身(转移所有权):

```rust
fn no_dangle() -> String {
    let s = String::from("hello");
    s // 所有权移出,调用方负责释放
}
```

## 切片:一种特殊的引用

### 字符串切片 `&str`

```rust
let s = String::from("hello world");

let hello: &str = &s[0..5];   // "hello"
let world: &str = &s[6..11];  // "world"
let all: &str = &s[..];       // "hello world"
```

切片的本质是:一个**指针** + 一个**长度**,不拥有底层数据.

```text
&str 内存布局(栈):
+--------+--------+
| 指针    | 长度    |
| (usize) | (usize) |
+--------+--------+
   |        5
   v
+---+---+---+---+---+
| h | e | l | l | o |
+---+---+---+---+---+
   堆(或数据段)
```

### 数组切片 `&[T]`

```rust
let a = [1, 2, 3, 4, 5];
let slice: &[i32] = &a[1..3]; // 引用 a 的一部分,而非复制
assert_eq!(slice, &[2, 3]);
```

/// info | 切片是胖指针
切片`&[T]`和`&str`由两部分组成:

1. **指针**:指向数据起始地址
2. **长度**:元素个数

因此占 16 字节(x86-64),而普通引用`&T`只占 8 字节.
///

### 切片作为函数参数

```rust
fn first_word(s: &str) -> &str {  // 接受 &str,无论调用方是 String 还是字面量
    let bytes = s.as_bytes();
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[..i];
        }
    }
    s
}

fn main() {
    let s = String::from("hello world");
    let word = first_word(&s);        // &String 可自动转为 &str

    let literal = "hello world";
    let word2 = first_word(literal);  // 字面量本身就是 &str
}
```

/// important | 优先用 &str 而非 &String
`&str` 可以接受 `&String` 和 `&str` 两种参数(通过 Deref 强制转换),
而 `&String` 只能接受 `&String`.编写 API 时优先使用 `&str`.
///

## 常见借用错误

### 错误一:同时持有不可变和可变引用

```rust
let mut v = vec![1, 2, 3];

let first = &v[0];  // 不可变借用
v.push(4);          // 错误:不能在有不可变借用时修改
println!("{first}");
```

### 错误二:在循环中修改集合

```rust
let mut v = vec![1, 2, 3];

for item in &v {     // 不可变借用 v
    v.push(*item);   // 错误:不能在迭代期间修改 v
}
```

### 错误三:返回局部变量的引用

```rust
fn return_ref() -> &i32 {
    let x = 42;
    &x // 错误:x 在函数返回后被释放
}
```

/// info | 借用检查器是最严格的审查者
以上错误都会被 Rust 编译器在一开始就拦截.虽然初学时可能觉得严格,但长期来看,它让你对程序的内存行为有了完全的掌控.
///

/// important | 引用与借用核心要点
引用机制让 Rust 在保持所有权系统零运行时开销的同时,实现了灵活,安全的数据访问.
掌握 `&T` 和 `&mut T` 的区别,遵守借用规则,理解切片,是写出地道的 Rust 代码的基础.
///
