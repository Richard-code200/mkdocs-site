# Rust 项目代码组织

Rust 项目的代码组织主要依靠 **Package**、**Crate** 和 **Module** 三个层次完成:

- **Package**:由 `Cargo.toml` 定义的项目,可以包含多个 crate.
- **Crate**:Rust 的编译单元,分为 binary crate 和 library crate.
- **Module**:crate 内部用于划分代码、管理命名空间和控制可见性的单元.

模块的文件路径只是模块树的物理组织方式,真正决定模块关系的是代码中的 `mod` 声明.

## Cargo 项目结构

### 二进制项目

使用下面的命令创建二进制项目:

```bash
cargo new csv_to_json
```

默认目录结构:

```text
csv_to_json/
├── Cargo.toml
└── src/
    └── main.rs
```

`src/main.rs` 是 binary crate 的根模块,其中的 `fn main()` 是程序入口.

### 库项目

使用下面的命令创建库项目:

```bash
cargo new csv_to_json --lib
```

目录结构:

```text
csv_to_json/
├── Cargo.toml
└── src/
    └── lib.rs
```

`src/lib.rs` 是 library crate 的根模块,可以被项目中的 binary crate 或其他项目引用.

### 同时包含库和程序

一个 Package 可以同时包含 `src/lib.rs` 和 `src/main.rs`:

```text
csv_to_json/
├── Cargo.toml
└── src/
    ├── lib.rs
    └── main.rs
```

此时它包含:

- 一个名为 `csv_to_json` 的 library crate.
- 一个名为 `csv_to_json` 的 binary crate.

虽然二者属于同一个 Package,但 `main.rs` 和 `lib.rs` 是两个不同的 crate 根.程序入口不会自动获得 `lib.rs` 中的私有模块,需要通过公开 API 使用库代码.

```rust
// src/lib.rs
pub fn convert() {
    println!("convert csv to json");
}
```

```rust
// src/main.rs
fn main() {
    csv_to_json::convert();
}
```

### 多个二进制程序

除了 `src/main.rs`,还可以在 `src/bin/` 下放置多个程序:

```text
src/
├── lib.rs
└── bin/
    ├── import.rs
    └── export.rs
```

每个文件都会成为一个独立的 binary crate,可以分别运行:

```bash
cargo run --bin import
cargo run --bin export
```

## 模块的三种组织方式

### 内联模块

模块内容直接写在当前文件中:

```rust
mod parser {
    pub fn parse() {
        println!("parse data");
    }
}

fn main() {
    parser::parse();
}
```

内联模块适合内容较少、只在一个文件中使用的代码.

### 单文件模块

`mod parser;` 声明模块后,Rust 会查找对应的模块文件.

```text
src/
├── main.rs
└── parser.rs
```

```rust
// src/main.rs
mod parser;

fn main() {
    parser::parse();
}
```

```rust
// src/parser.rs
pub fn parse() {
    println!("parse data");
}
```

`parser.rs` 对应模块路径 `crate::parser`.

### 目录模块

当一个模块包含多个子模块时,可以使用目录保存子模块:

```text
src/
├── main.rs
└── parser/
    ├── mod.rs
    ├── csv.rs
    └── json.rs
```

```rust
// src/main.rs
mod parser;
```

```rust
// src/parser/mod.rs
pub mod csv;
pub mod json;
```

```rust
// src/parser/csv.rs
pub fn parse() {}
```

```rust
// src/parser/json.rs
pub fn write() {}
```

调用路径:

```rust
parser::csv::parse();
parser::json::write();
```

`mod.rs` 是目录模块的传统入口文件,仍然有效.较新的项目也经常使用 `parser.rs` 作为父模块文件,再使用 `parser/` 保存子模块:

```text
src/
├── parser.rs
└── parser/
    ├── csv.rs
    └── json.rs
```

```rust
// src/parser.rs
pub mod csv;
pub mod json;
```

这种写法不需要 `parser/mod.rs`,通常更适合作为新项目的默认组织方式.

/// warning | 同名文件和目录不能并存
不要同时创建 `src/parser.rs` 和 `src/parser/` 作为同一个模块的入口.二者会产生模块定义冲突.应选择 `parser.rs` 或 `parser/mod.rs` 其中一种.
///

## 模块声明与文件路径

Rust 不会因为文件存在就自动把它加入模块树.每个文件模块都必须由父模块使用 `mod` 声明:

```text
src/
├── lib.rs
└── models/
    ├── mod.rs
    └── user.rs
```

```rust
// src/lib.rs
pub mod models;
```

```rust
// src/models/mod.rs
pub mod user;
```

对应的模块路径为:

```text
crate::models
└── crate::models::user
```

如果 `models/mod.rs` 中没有 `pub mod user;` 或 `mod user;`,那么 `user.rs` 虽然存在,但不会被编译器视为 `models` 的子模块.

常见文件映射规则:

| 模块声明               | Rust 查找的文件                   |
| ---------------------- | --------------------------------- |
| `mod foo;`             | `foo.rs` 或 `foo/mod.rs`          |
| `mod foo { mod bar; }` | `foo/bar.rs` 或 `foo/bar/mod.rs`  |
| `pub mod foo;`         | 与 `mod foo;` 相同,但模块对外公开 |

## 模块可见性

Rust 中模块、函数、结构体和字段默认都是私有的.路径中的每一层都必须满足可见性要求:

```rust
// src/lib.rs
pub mod models {
    pub mod user {
        pub fn create() {}
    }
}
```

外部代码才能调用:

```rust
csv_to_json::models::user::create();
```

如果某一层没有 `pub`,外部代码就无法通过该层访问后面的内容:

```rust
pub mod models {
    mod user {
        pub fn create() {}
    }
}
```

这里 `models` 是公开的,但 `user` 是私有的,因此外部代码不能调用 `models::user::create()`.

常用可见性形式:

```rust
pub fn public_api() {}              // 对外公开
pub(crate) fn crate_api() {}        // 当前 crate 内可见
pub(super) fn parent_api() {}       // 父模块可见
fn private_api() {}                 // 默认私有
```

## 模块路径

### `crate`

`crate` 表示当前 crate 的根模块,适合在 crate 内使用绝对路径:

```rust
crate::models::user::create();
```

### `self`

`self` 表示当前模块:

```rust
use self::user::create;
```

### `super`

`super` 表示父模块:

```rust
mod models {
    fn validate() {}

    mod user {
        fn create() {
            super::validate();
        }
    }
}
```

### 外部 crate 名称

在同一个 Package 的 `main.rs` 中访问 `lib.rs` 的公开内容时,通常使用 Package 名称作为 crate 名称:

```rust
// src/main.rs
use csv_to_json::models::user::create;

fn main() {
    create();
}
```

## 简化模块调用

### 使用 `use`

完整路径较长时,可以使用 `use` 将内容导入当前作用域:

```rust
use crate::models::user::create;

fn run() {
    create();
}
```

也可以只导入模块,保留模块前缀:

```rust
use crate::models::user;

fn run() {
    user::create();
}
```

导入模块通常更容易看出函数的来源,适合项目中的通用代码.

### 使用 `as` 设置别名

两个模块中存在同名内容时,可以使用 `as` 重命名:

```rust
use crate::models::user::create as create_user;
use crate::models::admin::create as create_admin;

fn run() {
    create_user();
    create_admin();
}
```

### 使用 `pub use` 重新导出

如果不希望调用方依赖过深的内部路径,可以在较高层模块重新导出内容:

```rust
// src/lib.rs
pub mod models;
pub use models::user::create;
```

外部代码只需要调用:

```rust
use csv_to_json::create;

fn main() {
    create();
}
```

`pub use` 适合设计库的公共 API.内部目录可以继续调整,调用方不需要跟着修改很深的路径.

## `csv_to_json` 项目示例

一个使用模型模块的项目可以组织为:

```text
csv_to_json/
├── Cargo.toml
└── src/
    ├── lib.rs
    ├── main.rs
    └── models/
        ├── mod.rs
        ├── enums.rs
        └── record.rs
```

```rust
// src/lib.rs
pub mod models;
```

```rust
// src/models/mod.rs
pub mod enums;
pub mod record;
```

```rust
// src/models/enums.rs
pub mod input {
    pub fn validate() {}
}

pub mod output {
    pub fn format() {}
}
```

```rust
// src/main.rs
use csv_to_json::models::enums::input;

fn main() {
    input::validate();
}
```

此时模块路径为:

```text
csv_to_json::models::enums::input::validate
```

如果这个路径过深,可以在 `lib.rs` 中重新导出:

```rust
pub use models::enums::input::validate;
```

然后在 `main.rs` 中直接使用:

```rust
use csv_to_json::validate;

fn main() {
    validate();
}
```

## 按职责组织项目

小项目可以按功能划分文件:

```text
src/
├── main.rs
├── models.rs
├── parser.rs
└── writer.rs
```

当项目变大时,可以为每种职责建立目录:

```text
src/
├── main.rs
├── lib.rs
├── models/
│   ├── mod.rs
│   ├── record.rs
│   └── enums.rs
├── parser/
│   ├── mod.rs
│   └── csv.rs
├── writer/
│   ├── mod.rs
│   └── json.rs
└── error.rs
```

常见职责划分:

| 模块       | 主要职责                 |
| ---------- | ------------------------ |
| `models`   | 数据结构、枚举和领域模型 |
| `parser`   | 输入数据解析和校验       |
| `writer`   | 输出数据和格式转换       |
| `error`    | 自定义错误类型           |
| `config`   | 配置加载和配置类型       |
| `services` | 跨模块的业务流程         |

划分模块时应优先按照职责和领域边界组织,而不是简单地把每个函数拆到不同文件中.文件数量过多会增加路径和维护成本.

/// info | 模块命名建议
模块和文件通常使用 `snake_case`,类型使用 `PascalCase`,函数和变量使用 `snake_case`.例如 `user_record.rs`、`UserRecord` 和 `parse_record`.
///

## Workspace 组织多个项目

当多个 crate 关系密切时,可以使用 Cargo workspace:

```text
workspace/
├── Cargo.toml
├── csv_to_json/
│   ├── Cargo.toml
│   └── src/
└── csv_common/
    ├── Cargo.toml
    └── src/
```

workspace 根目录的 `Cargo.toml`:

```toml
[workspace]
members = ["csv_to_json", "csv_common"]
resolver = "3"
```

`csv_to_json/Cargo.toml` 可以通过路径依赖使用公共库:

```toml
[dependencies]
csv_common = { path = "../csv_common" }
```

常用命令:

```bash
cargo check                         # 检查所有 workspace 成员
cargo check -p csv_to_json          # 只检查指定 crate
cargo test -p csv_to_json           # 测试指定 crate
```

### 当前学习仓库的层级

`Rust_Lang/Cargo.toml` 只有 `[workspace]`,因此仓库根是 virtual workspace,不是 Package,也不会因根目录本身产生 binary crate.其中每个成员目录(例如 `nth_fibonacci/`)各自包含 `Cargo.toml`,所以成员是 **Package**:

```text
Rust_Lang/                         # Workspace
├── Cargo.toml                    # [workspace] 与 members
├── nth_fibonacci/                # Package
│   ├── Cargo.toml                # [package]
│   └── src/main.rs               # 默认 binary crate 的 crate 根
└── temp_converter/               # 另一个 Package
    ├── Cargo.toml
    └── src/main.rs               # 另一个 binary crate
```

`src/main.rs` 既是默认 binary crate 的根模块,其中的 `fn main()` 又是可执行程序入口.因此 Workspace、Package、binary crate 和 `src/main.rs` 是四个不同层级,不能把 workspace 成员直接称为 `.rs` 文件.

## 常见问题检查

### 文件存在但模块找不到

确认父模块中是否声明了子模块:

```rust
// src/models/mod.rs
pub mod record;
```

### 模块路径正确但无法访问

从路径的每一层检查 `pub`:

```rust
pub mod models {
    pub mod record {
        pub fn parse() {}
    }
}
```

### `main.rs` 无法访问 `lib.rs`

确认库模块和要调用的项都是公开的,并通过 Package 名称访问:

```rust
use csv_to_json::models::record::parse;
```

不要在 `main.rs` 中再次声明同一组库模块,否则会创建另一棵独立的模块树.

### 检查项目结构

可以使用下面的命令检查项目:

```bash
cargo check
cargo test
cargo tree
```

/// important | 核心原则
文件路径负责承载代码,`mod` 声明负责建立模块树,`pub` 负责控制可见性,`use` 负责简化调用路径.设计项目结构时,应先确定模块职责和公开 API,再决定文件和目录如何组织.
///
