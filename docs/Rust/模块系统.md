# 模块系统

Rust 的模块系统让你组织代码结构,控制可见性(公开 / 私有),管理命名空间.

## 包与 Crate

- **包**(Package):由 `Cargo.toml` 定义,包含一个或多个 crate
- **Crate**:一个编译单元,可以是二进制程序(bin)或库(lib)
- **模块**(Module):crate 内部的代码组织单位

```bash
cargo new my_project         # 创建二进制包
cargo new my_lib --lib       # 创建库包
```

/// info | 包的规则
一个包最多包含**一个**库 crate 和**多个**二进制 crate.每个 `src/main.rs` 对应一个二进制 crate,`src/lib.rs` 对应库 crate.
///

## mod -- 定义模块

`mod` 关键字用于定义模块,模块可以嵌套:

```rust
mod front_of_house {
    mod hosting {
        fn add_to_waitlist() {}
        fn seat_at_table() {}
    }
    mod serving {
        fn take_order() {}
        fn server_order() {}
        fn take_payment() {}
    }
}
```

模块形成一棵**模块树**:

```
crate
└── front_of_house
    ├── hosting
    │   ├── add_to_waitlist
    │   └── seat_at_table
    └── serving
        ├── take_order
        ├── server_order
        └── take_payment
```

## 路径 -- 如何引用模块中的项

使用路径(Path)来引用模块中的函数、结构体等:

```rust
// 绝对路径:从 crate 根开始
crate::front_of_house::hosting::add_to_waitlist();

// 相对路径:从当前模块开始
front_of_house::hosting::add_to_waitlist();
```

/// info | 路径分隔符 `::`
`::` 是 Rust 的路径分隔符,类似文件系统的 `/`.它用于连接模块名和项名.
///

## pub -- 可见性控制

Rust 中所有项**默认私有**.使用 `pub` 关键字公开:

```rust
mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {}
    }
}

fn eat_at_restaurant() {
    crate::front_of_house::hosting::add_to_waitlist();
}
```

/// warning | 可见性规则
- 模块本身需要 `pub`,其内部的项也需要单独 `pub`
- 结构体的字段默认私有,需要逐个 `pub`
- 枚举的变体在枚举 `pub` 后自动公开
///

### pub 的多种形式

```rust
pub(crate) fn internal_api() {}     // 仅 crate 内可见
pub(super) fn parent_visible() {}   // 父模块可见
pub(in crate::front_of_house)       // 指定路径可见
fn private_function() {}            // 默认私有
```

## use -- 导入到作用域

`use` 将路径引入当前作用域,避免每次写完整路径:

```rust
use crate::front_of_house::hosting;

fn eat_at_restaurant() {
    hosting::add_to_waitlist();
}
```

### 导入惯例

```rust
use std::collections::HashMap;          // 导入结构体/枚举
use std::io::{self, Read, Write};       // 一次导入多个
use std::io::Result;                    // 导入类型别名
use std::fmt::Display as FmtDisplay;    // 重命名避免冲突
```

/// info | 导入函数的惯例
导入**模块**而非函数本身,调用时保留模块前缀,让代码来源更清晰:

```rust
use std::io;                           // 推荐:导入模块
io::stdin().read_line(&mut input);     // 调用时知道来自 std::io

use std::io::stdin;                    // 不推荐:直接导入函数
stdin().read_line(&mut input);         // 不清楚来源
```

///

### 使用 `as` 重命名

当两个模块有同名项时:

```rust
use std::fmt;
use std::io;

fn function1() -> fmt::Result {}
fn function2() -> io::Result<()> {}
```

或者用 `as` 重命名:

```rust
use std::fmt::Result;
use std::io::Result as IoResult;

fn function1() -> Result {}
fn function2() -> IoResult<()> {}
```

### 使用 `pub use` 重新导出

```rust
pub use crate::front_of_house::hosting;
// 外部代码可以通过当前模块的路径访问 hosting
```

## 文件组织

### 单文件模块

```rust
mod front_of_house;  // 在 main.rs 或 lib.rs 中声明
// Rust 会在 src/front_of_house.rs 中查找模块内容
```

### 目录模块

```
src/
├── main.rs                    # crate 根
├── front_of_house.rs          # front_of_house 模块
└── front_of_house/
    └── hosting.rs             # hosting 子模块
```

```rust
// src/main.rs
mod front_of_house;

// src/front_of_house.rs
pub mod hosting;

// src/front_of_house/hosting.rs
pub fn add_to_waitlist() {}
```

/// info | 文件查找规则

| 声明 | 查找顺序 |
| ---- | -------- |
| `mod foo;` | `src/foo.rs` → `src/foo/mod.rs` |
| `mod foo { mod bar; }` | `src/foo/bar.rs` → `src/foo/bar/mod.rs` |

两种方式等价,推荐 `src/foo.rs` 风格(更简洁).
///

## super -- 访问父模块

`super` 用于从子模块引用父模块的内容:

```rust
fn serve_order() {}

mod back_of_house {
    fn fix_incorrect_order() {
        cook_order();
        super::serve_order();
    }

    fn cook_order() {}
}
```

## crate -- crate 根

`crate` 关键字表示当前 crate 的根模块,用于绝对路径:

```rust
mod front_of_house {
    pub mod hosting {
        pub fn add_to_waitlist() {}
    }
}

fn eat_at_restaurant() {
    crate::front_of_house::hosting::add_to_waitlist();
}
```

## Cargo Workspace -- 管理多个 crate

当一个项目包含多个相关的 crate 时,使用 workspace 统一管理:

```toml
# Cargo.toml (workspace 根)
[workspace]
members = [
    "variables_learn",
    "ownership_learn",
    "struct_learn",
]
resolver = "3"
```

workspace 的特点:

- 所有成员共享 `Cargo.lock`,确保依赖版本一致
- 使用 `cargo build -p crate_name` 构建单个成员
- 使用 `cargo test -p crate_name` 测试单个成员
- `cargo build` 默认构建所有成员

/// info | workspace vs 多个独立项目

| | workspace | 独立项目 |
| ---- | --------- | -------- |
| 依赖管理 | 共享 Cargo.lock | 各自独立 |
| 编译缓存 | 共享 target/ | 各自独立 |
| 跨 crate 引用 | 方便(path 依赖) | 需要发布到 crates.io |
| 适用场景 | 相关组件 | 独立项目 |
///

### workspace 中的 path 依赖

```toml
# members/my_app/Cargo.toml
[dependencies]
my_lib = { path = "../my_lib" }
```

## 实战示例:学习项目的模块组织

```rust
// src/main.rs
#![allow(unused)]
use std::io;
mod array_and_vector;
mod borrowing_and_references;
mod enum_ex;
mod function_and_fllow;
mod ownership;
mod slice;
mod structs;

fn main() {
    ownership::ownership();
}
```

每个 `mod xxx;` 对应 `src/xxx.rs` 文件,形成了清晰的模块结构:

```
src/
├── main.rs                      # 入口,声明所有模块
├── variables.rs                 # 变量与数据类型
├── function_and_fllow.rs        # 函数与控制流
├── ownership.rs                 # 所有权
├── borrowing_and_references.rs  # 借用与引用
├── slice.rs                     # 切片
├── structs.rs                   # 结构体
├── enum_ex.rs                   # 枚举
└── ...
```

/// important | 模块系统核心要义
模块系统是 Rust 代码组织的基石.通过 `mod` 划分逻辑单元,`pub` 控制可见性,`use` 简化路径引用,配合 workspace 管理大型项目,让你的代码结构清晰,可维护.
///
