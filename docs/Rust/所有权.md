# 所有权

## 什么是所有权

**所有权**是确保 Rust 程序安全的一种机制.所谓"安全",是指程序中没有未定义行为(Undefined Behavior).

/// info | 未定义行为
当执行一段代码时,结果不可预测且未被编程语言指定的情况.Rust 的基础目标是**确保你的程序永远不会有未定义行为**,次要目标是在**编译时**而非运行时防止未定义行为.
///

大多数语言在运行时才会抛出异常,而 Rust 的目标是尽可能减少运行时的检查——Rust 在编译时就会进行错误分析和抛出.

```rust
fn main() {
    read(x); // 编译错误:cannot find value `x` in this scope
    let x = true;
}

fn read(y: bool) {
    if y {
        println!("y is true!");
    }
}
```

```bash
cargo run --bin owenership
   Compiling owenership v0.1.0
error[E0425]: cannot find value `x` in this scope
 --> owenership/src/main.rs:2:10
  |
2 |     read(x);
  |          ^ not found in this scope
```

## 所有权规则

所有权有三条基本原则:

1. Rust 中的每一个值都有一个**所有者**(Owner)
2. 值在任意时刻**有且只有一个**所有者
3. 当所有者离开作用域,这个值将被**丢弃**(Drop)

/// important | 所有权是 Rust 最独特的特性
所有权机制让 Rust 无需垃圾回收器(GC)就能保障内存安全.其他语言通过 GC 或手动内存管理来保证安全,Rust 则通过编译期检查所有权规则来实现,真正做到了**零运行时开销**.
///

## 栈(Stack)与堆(Heap)

### 栈

栈中的所有数据都必须占用已知且固定的大小,数据以"后进先出"(LIFO)的方式管理.

```rust
fn main() {
    let n = 5;                    // L1: main 栈帧压入 n=5
    let y = plus_one(n);          // L3: main 栈帧压入 y=6
    println!("The value of y is: {y}");
}

fn plus_one(x: i32) -> i32 {
    x + 1                         // L2: plus_one 栈帧压入 x=5
}
```

| L1(Stack) | L2(Stack)     | L3(Stack)     |
| --------- | ------------- | ------------- |
| main(n:5) | main(n:5)     | main(n:5,y:6) |
|           | plus_one(x:5) |               |

- 函数调用时,参数和局部变量被推入栈
- 函数返回时,其栈帧被弹出,变量随之释放

### 堆

对于编译时大小未知或可能变化的数据,存储在堆上:

```rust
let s = String::from("hello"); // 字符串数据在堆上,栈上存放指针
```

- 分配内存时,操作系统在堆中找到足够大的空间,标记为已用,返回**指针**
- 栈上存放的是指向堆的指针,长度,容量等信息

/// info | 栈 vs 堆

|      | 栈(Stack)             | 堆(Heap)                |
| ---- | --------------------- | ----------------------- |
| 速度 | 快(直接访问)          | 慢(通过指针间接访问)    |
| 大小 | 固定,编译时已知       | 动态,运行时分配         |
| 管理 | 自动(LIFO)            | 手动 / 所有权机制       |
| 用途 | 简单类型(i32,bool 等) | 复杂类型(String,Vec 等) |

///

## 变量作用域

```rust
{                          // s 在这里无效,它尚未声明
    let s = "hello";       // s 从此处开始有效
    // 使用 s
}                          // 此作用域已结束,s 不再有效
```

当变量离开作用域时,Rust 会自动调用 `drop` 函数释放内存.这与 C++ 的 RAII(Resource Acquisition Is Initialization)模式类似.

## 移动(Move)

考虑以下代码:

```rust
let x = 5;
let y = x; // x 的值被复制给 y(Copy trait)
```

但如果数据在堆上呢?

```rust
let s1 = String::from("hello");
let s2 = s1; // s1 被移动到 s2,s1 不再有效
```

`String` 在内存中的布局:

- **指针**(栈):指向堆中存放字符串内容的内存
- **长度**(栈):字符串当前使用的字节数
- **容量**(栈):从分配器获取的总字节数

当执行 `let s2 = s1;` 时,Rust 为了避免**双重释放**(double free),
会将 `s1` **移动**给 `s2`,此后 `s1` 不再有效:

```rust
let s1 = String::from("hello");
let s2 = s1;

println!("{s1}"); // 编译错误:use of moved value: `s1`
```

/// warning | 浅拷贝 vs 移动
Rust 永远不会自动创建数据的"深拷贝".默认的赋值或传参行为是**移动**(转移所有权),而非拷贝.这与许多语言的"浅拷贝默认"行为根本不同.
///

## 克隆(Clone)

如果确实需要深拷贝堆数据,可以使用 `clone` 方法:

```rust
let s1 = String::from("hello");
let s2 = s1.clone(); // 堆数据被完整复制,s1 仍然有效

println!("s1 = {s1}, s2 = {s2}"); // 正常执行
```

/// info | clone 的代价
`clone()` 会复制所有堆数据,开销可能较大.Rust 将这个操作显式化——当你看到 `clone` 时,就知道这里发生了一次完整的深拷贝,有助于关注性能.
///

## Copy trait

对于像整数这样完全存放在栈上的类型,Rust会自动复制:

```rust
let x = 5;
let y = x;

println!("x = {x}, y = {y}"); // 正常,因为 i32 实现了 Copy
```

如果一种类型实现了 `Copy` trait,那么赋值后旧变量仍然可用.Rust 不允许自身或其任何部分实现了 `Drop` trait 的类型使用 `Copy`.

实现了 `Copy` 的常见类型:

- 所有整数类型(`u32`,`i64` 等)
- 所有浮点类型(`f32`,`f64`)
- 布尔类型(`bool`)
- 字符类型(`char`)
- 元组,当且仅当其包含的每个元素都实现了 `Copy`
- 不可变引用 `&T`

/// important | Copy vs Clone
`Copy` 是**隐式的,按位复制**,不会影响原值;`Clone` 是**显式的,可自定义的深拷贝**.实现了 `Copy` 的类型通常也实现了 `Clone`.
///

## 所有权与函数

```rust
fn main() {
    let s = String::from("hello"); // s 进入作用域
    takes_ownership(s);            // s 的值移动到函数,此后 s 无效

    let x = 5;                     // x 进入作用域
    makes_copy(x);                 // x 被复制(i32 是 Copy),此后 x 仍有效

} // x 离开作用域,s 已经移动所以无事发生

fn takes_ownership(some_string: String) {
    println!("{some_string}");
} // some_string 离开作用域,drop 被调用

fn makes_copy(some_integer: i32) {
    println!("{some_integer}");
} // some_integer 离开作用域
```

返回值也可以转移所有权:

```rust
fn main() {
    let s1 = gives_ownership();         // 返回值移动给 s1
    let s2 = String::from("hello");
    let s3 = takes_and_gives_back(s2);  // s2 移入函数,返回值移给 s3
}

fn gives_ownership() -> String {
    let some_string = String::from("yours");
    some_string // 返回并移出
}

fn takes_and_gives_back(a_string: String) -> String {
    a_string // 返回并移出
}
```

## 引用与借用

每次都要把所有权传来传去太麻烦了.**引用**(Reference)允许在不获取所有权的情况下使用值:

```rust
fn main() {
    let s1 = String::from("hello");
    let len = calculate_length(&s1); // 传递引用而非所有权
    println!("The length of '{s1}' is {len}.");
} // s1 仍然有效

fn calculate_length(s: &String) -> usize {
    s.len()
} // s 离开作用域,但不拥有引用值的所有权,不会调用 drop
```

`&` 符号表示**引用**,它允许使用值但不获取其所有权.把创建一个引用的行为称为**借用**(Borrowing).

```rust
let s1 = String::from("hello");
let s2 = &s1; // s2 借用了 s1
```

/// info | 借用的比喻
借用的本质是"暂时使用,用完归还".你不拥有它,只是临时访问.当你用完或引用离开作用域后,借用关系就结束了.
///

## 可变引用

默认情况下,引用是不可变的:

```rust
let mut s = String::from("hello");
let r = &mut s; // 创建可变引用
r.push_str(", world!");
println!("{s}"); // "hello, world!"
```

可变引用有一个重要限制:**在任意给定时间,要么只能有一个可变引用,要么只能有多个不可变引用**.

```rust
let mut s = String::from("hello");

let r1 = &mut s;
let r2 = &mut s; // 编译错误:cannot borrow `s` as mutable more than once at a time

let r3 = &s;
let r4 = &s;
let r5 = &mut s; // 编译错误:不能同时存在可变引用和不可变引用
```

/// warning | 数据竞争
多个可变引用同时存在会导致**数据竞争**(Data Race),这在 C/C++ 中是 UB 的来源之一.Rust 在编译期就禁止这种情况,从根本上消除了数据竞争.
///

**引用的作用域**从声明开始,持续到**最后一次使用**为止:

```rust
let mut s = String::from("hello");

let r1 = &s;
let r2 = &s;
println!("{r1} {r2}"); // r1 和 r2 在此之后不再使用

let r3 = &mut s; // 没问题,因为 r1 和 r2 的作用域已经结束
println!("{r3}");
```

这种编译器优化称为非词法作用域生命周期(NLL, Non-Lexical Lifetimes).

/// important | 借用规则总结

1. 在任意给定时间,**要么**有一个可变引用,**要么**有任意多个不可变引用
2. 引用**必须**总是有效的(不能有悬垂引用)
   ///

## 悬垂引用(Dangling References)

悬垂指针:指向已经被释放或分配给其他人的内存地址的指针.Rust 中,编译器保证引用永远不会变成悬垂引用:

```rust
fn dangle() -> &String {
    let s = String::from("hello");
    &s // 编译错误:`s` does not live long enough
} // s 在这里离开作用域并被释放
```

编译器会精确分析引用的生命周期,确保任何引用都不会比其引用的数据活得更长.

## 切片(Slice)

**切片**(Slice)是一种不获取所有权的引用,它引用集合中一段**连续的元素序列**:

```rust
let s = String::from("hello world");

let hello = &s[0..5]; // "hello"
let world = &s[6..11]; // "world"
```

切片的区间语法:

```rust
let s = String::from("hello");

let slice = &s[0..2]; // "he" —— 索引 0 和 1
let slice = &s[..2];  // 同上,从 0 开始可省略
let slice = &s[3..];  // "lo" —— 从索引 3 到末尾
let slice = &s[..];   // "hello" —— 整个字符串
```

```rust
fn first_word(s: &String) -> &str {
    let bytes = s.as_bytes();
    for (i, &item) in bytes.iter().enumerate() {
        if item == b' ' {
            return &s[0..i];
        }
    }
    &s[..]
}
```

/// info | 字符串切片 vs 字符串字面量
字符串字面量 `"hello"` 的类型就是 `&str`,它是一个指向二进制程序特定位置的切片.正因如此,字符串字面量是不可变的.
///

其他集合类型同样支持切片:

```rust
let a = [1, 2, 3, 4, 5];
let slice = &a[1..3]; // 类型为 &[i32],指向 [2, 3]
```

## Box<T> -- 堆上分配

`Box<T>` 是 Rust 中最简单的**智能指针**(Smart Pointer),它允许将数据存储在**堆**上,而栈上只保留指向堆数据的指针.

### 基本用法

```rust
let b = Box::new(5);
println!("b = {b}");
// b 离开作用域时,Box 和它指向的堆数据一起被释放
```

`Box<T>` 的核心特点:

- 数据在**堆**上分配,栈上只存指针
- 遵循所有权规则:当 `Box` 离开作用域时,它和它指向的堆数据都会被释放
- 实现了 `Deref` trait,可以像普通引用一样解引用

/// info | Box 的内存布局

```
栈(Stack)          堆(Heap)
+------+          +-----+
| 指针 | --------> |  5  |
+------+          +-----+
(usize, 8字节)    (i32, 4字节)
```

`Box<T>` 本身在栈上只占用一个指针的大小(usize),实际数据在堆上.
///

### 使用场景

#### 场景一:递归类型

Rust 在编译时需要知道每个类型的大小,而递归类型的大小在编译时无法确定:

```rust
// 编译错误:recursive type has infinite size
enum List {
    Cons(i32, List),
    Nil,
}
```

使用 `Box<T>` 解决,因为 `Box` 是指针,大小固定:

```rust
enum List {
    Cons(i32, Box<List>),
    Nil,
}

use List::{Cons, Nil};

fn main() {
    let list = Cons(1, Box::new(Cons(2, Box::new(Cons(3, Box::new(Nil))))));
}
```

`Cons` 的内存布局:

- 栈上:`(i32, Box指针)` -- 大小已知
- 堆上:`(i32, Box指针)` -> `(i32, Box指针)` -> `Nil`

/// important | 为什么递归类型需要 Box
`List` 枚举在编译时需要确定最大变体的大小.如果 `Cons(i32, List)` 直接包含自身,编译器会陷入无限循环计算大小.`Box<List>` 是一个指针,大小固定为 `usize`,打破了递归.
///

#### 场景二:转移大量数据

当数据量很大时,直接移动会复制整个栈上数据.用 `Box` 可以只转移指针:

```rust
let large_data = Box::new([0u8; 1024 * 1024]); // 1MB 数据在堆上
let moved_data = large_data;                    // 只转移指针(8 字节),数据不动
// large_data 在此之后不可用
```

/// info | Box 与所有权
`Box<T>` 完全遵守所有权规则:赋值会**移动**所有权,离开作用域时自动释放.当你在函数间传递 `Box<T>` 时,只复制栈上的指针,堆数据不会发生拷贝.
///

#### 场景三:通过 Deref 自动解引用

```rust
let x = 5;
let y = Box::new(x);

assert_eq!(5, x);
assert_eq!(5, *y); // 显式解引用
assert_eq!(5, *(y.deref())); // 等价写法
```

`Box<T>` 实现了 `Deref` trait,可以用 `*` 解引用操作符访问内部数据.

### 解引用强制转换(Deref Coercion)

Rust 会自动将 `&Box<T>` 转换为 `&T`,让代码更自然:

```rust
fn hello(name: &str) {
    println!("Hello, {name}!");
}

let m = Box::new(String::from("Rust"));
hello(&m); // &Box<String> 自动转换为 &String -> &str
```

/// warning | Box 不是万能钥匙
优先使用**栈**分配的数据,只有在必要场景(递归类型,数据量过大,需要转移所有权而不拷贝)才使用 `Box`.过度使用堆分配会影响性能.
///

/// important | 所有权核心要义
所有权,借用,切片以及 `Box<T>` 这些概念,都在**编译时**保障了 Rust 程序的内存安全.Rust 通过所有权系统,让你不需要垃圾回收器,也无需手动管理内存,就能写出安全,高效的代码.
///
