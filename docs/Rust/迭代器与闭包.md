# 迭代器与闭包

本篇整理 minigrep 中实际练习过的迭代器操作:参数消费、惰性转换、文本过滤和原文件行号.搜索的借用关系见[生命周期](生命周期.md),参数入口见[命令行文件搜索实践](命令行文件搜索实践.md).

## next:取得并消费下一个元素

迭代器按需产生元素.`next()` 返回 `Option<Item>` 并推进当前位置,不是只查看而不消费:

```rust
let mut args = ["minigrep", "Rust", "poem.txt"].into_iter();
assert_eq!(args.next(), Some("minigrep"));
assert_eq!(args.next(), Some("Rust"));
assert_eq!(args.next(), Some("poem.txt"));
assert_eq!(args.next(), None);
```

需要写 `mut args`,因为 next 会改变迭代器的状态.`std::env::args()` 产生 String,第一项通常是程序路径,参数解析时先消费掉这一项.

接收迭代器的签名可以写成:

```rust
// Config::build 的签名,实现见项目源码
// pub fn build(mut args: impl Iterator<Item = String>)
//     -> Result<Config, ConfigError>
```

`impl Iterator<Item = String>` 表示接受某种实现 Iterator 且元素为 String 的类型.它并不要求先收集成 Vec,也不是 dyn 动态派发.

## iter 与 into_iter:关注所有权

```rust
let words = vec![String::from("Rust"), String::from("Python")];
for word in words.iter() { // word: &String,借用元素
    println!("{word}");
}
assert_eq!(words.len(), 2); // 原 Vec 仍可使用

for word in words.into_iter() { // word: String,取得元素所有权
    println!("{word}");
}
// 这里不能再使用 words,Vec 已移入迭代器
```

不能机械地说“调用 into_iter 后原变量一定不能用”.数组在元素实现 Copy 时也实现 Copy,例如 `[&str; N]`:

```rust
let args = ["minigrep", "Rust", "poem.txt"];
let owned: Vec<String> = args.into_iter().map(String::from).collect();

assert_eq!(args[1], "Rust"); // 数组可 Copy,原变量仍能使用
assert_eq!(owned[1], "Rust");
```

这里 `.map(String::from)` 把每个 `&str` 转成拥有文本的 String,与 `.map(|arg| String::from(arg))` 对此例的作用相同.传给 Config::build 时可以直接传 map 产生的迭代器,无需 collect.

## map、filter 与 collect

| 操作 | 作用 | 是否立即处理所有元素 |
| ---- | ---- | -------------------- |
| `map(f)` | 用 f 的返回值替换每个元素,可改变类型 | 否 |
| `filter(p)` | 用 bool 决定保留与否,不替换原元素 | 否 |
| `collect()` | 消费迭代器并构造目标集合 | 是,此处会收集剩余元素 |

```rust
let query = "Rust";
let results: Vec<&str> = "Rust is fast.\nPython is readable.\nI like Rust."
    .lines()
    .filter(|line| line.contains(query))
    .collect();

assert_eq!(results, vec!["Rust is fast.", "I like Rust."]);
```

`|line| line.contains(query)` 是闭包:`|...|` 中是参数,后面的表达式是返回值.这个闭包捕获并读取外部的 query,不需要转移查询字符串的所有权.对这里的 Item = &str,filter 的谓词接收对元素的引用,方法调用会处理相应解引用.

collect 根据目标类型推断要构造什么集合.也可以把类型写在调用处:

```rust
let lines = "Rust\nPython".lines().collect::<Vec<_>>();
assert_eq!(lines, vec!["Rust", "Python"]);
```

### 惰性求值

map 和 filter 是惰性的.没有消费者请求元素时,闭包不会执行;只取一个元素也不代表剩下的全部被处理:

```rust
let mut count = 0;
{
    let mut args = ["minigrep", "Rust", "poem.txt"].into_iter().map(|arg| {
        count += 1;
        String::from(arg)
    });
    assert_eq!(args.next(), Some(String::from("minigrep")));
} // 迭代器被丢弃,剩余两项不执行 map
assert_eq!(count, 1);
```

## lines 与原文保持

`str::lines()` 返回原文中的行切片,不复制每行字符串.行分隔符不包含在返回的切片中;中间空行会产生空字符串,末尾换行不会额外增加一条空行:

```rust
assert_eq!("Rust\n\nPython\n".lines().collect::<Vec<_>>(), vec!["Rust", "", "Python"]);
assert!("".lines().next().is_none());
assert!("anything".contains("")); // 空查询匹配所有由 lines 产生的行
```

不要随意 trim:原文的缩进和行首尾空格可能是数据.多行字符串字面量中的缩进也可能实际进入测试素材.

### 忽略大小写,但返回原始行

```rust
fn search_case_insensitive<'a>(query: &str, contents: &'a str) -> Vec<&'a str> {
    let lowercase_query = query.to_lowercase();
    contents
        .lines()
        .filter(|line| line.to_lowercase().contains(lowercase_query.as_str()))
        .collect()
}

assert_eq!(search_case_insensitive("rUsT", "  RUST is useful.\nPython"), vec!["  RUST is useful."]);
```

- to_lowercase 创建新的 String;查询词在循环外转换一次,每行在判断时转换.
- filter 只用小写结果判断,保留的仍是原始 line,所以大小写、顺序和缩进不变.
- 返回借自临时小写 String 的切片既会丢失原文,也不能满足返回值的生命周期.

本项目的忽略大小写规则就是双方 to_lowercase 后比较,不等同于完整的 Unicode 大小写折叠方案.

## enumerate:先编号,再过滤

enumerate 产生 `(usize, 元素)` 元组,编号从 0 开始.要保留**原文件行号**,顺序必须是:

```rust
fn search_with_line_numbers<'a>(query: &str, contents: &'a str) -> Vec<(usize, &'a str)> {
    contents
        .lines()
        .enumerate()
        .filter(|(_, line)| line.contains(query))
        .map(|(index, line)| (index + 1, line))
        .collect()
}

assert_eq!(
    search_with_line_numbers("Rust", "Rust\nPython\nRust again"),
    vec![(1, "Rust"), (3, "Rust again")],
);
```

`(_, line)` 忽略编号,只对文本判断;`(index, line)` 解构元组,将编号加 1 后组成新的元组.若先 filter 再 enumerate,得到的是“匹配结果中的序号”,会错误地变成 1 和 2.

忽略大小写并显示行号时,仍按这个顺序,仅把谓词换成小写比较.当前返回 `Vec<(usize, &str)>`,每行文字仍借自原文.
