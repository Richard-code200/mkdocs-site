# 撤销与回退

## 撤销工作区修改

```bash
# 撤销工作区中某个文件的修改（回到最近一次 git add 或 git commit 的状态）
git restore <filename>

# 撤销所有工作区修改
git restore .

# 旧版写法（功能相同）
git checkout -- <filename>
```

## 撤销暂存区修改

```bash
# 将文件从暂存区移出，但保留工作区的修改
git restore --staged <filename>

# 取消所有暂存
git restore --staged .

# 旧版写法
git reset HEAD <filename>
```

## 修改提交

```bash
# 修改最近一次提交的提交信息
git commit --amend -m "新的提交信息"

# 向最近一次提交添加遗漏的文件（不修改提交信息）
git add <遗漏的文件>
git commit --amend --no-edit

# 修改更早的提交（交互式 rebase）
git rebase -i HEAD~3
# 将需要修改的提交前的 pick 改为 edit，保存退出
# 修改文件后
git add <filename>
git commit --amend
git rebase --continue
```

## 回退提交

```bash
# 回退到指定提交，保留修改在工作区（软回退）
git reset --soft <commit-id>
git reset --soft HEAD~1  # 撤销最近一次提交

# 回退到指定提交，保留修改在暂存区
git reset --mixed <commit-id>  # --mixed 是默认选项

# 回退到指定提交，丢弃所有修改（危险！）
git reset --hard <commit-id>
git reset --hard HEAD~1        # 删除最近一次提交及其修改
```

## 撤销提交（保留历史）

```bash
# 创建一个新的提交来撤销之前的提交（推荐用于公共分支）
git revert <commit-id>

# 撤销最近一次提交
git revert HEAD

# 撤销多个提交
git revert <commit-id1>..<commit-id2>

# 不自动创建提交，只将修改应用到工作区
git revert --no-commit <commit-id>
```

## 清理未跟踪文件

```bash
# 查看哪些文件会被删除（干运行）
git clean -n

# 删除未跟踪的文件
git clean -f

# 删除未跟踪的文件和目录
git clean -fd

# 连 .gitignore 中忽略的文件也删除
git clean -xf
```

## 后悔药：找回丢失的提交

```bash
# 查看所有分支操作历史（包括已删除的提交）
git reflog

# 从 reflog 恢复
git reset --hard HEAD@{2}
```
