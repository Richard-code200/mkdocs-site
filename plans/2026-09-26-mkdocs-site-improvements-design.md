# 笔记站点六项优化设计

日期：2026-09-26

## 目标与边界

让访客在手机上直接开始阅读，统一中文站点标识，改善笔记入口和中文检索，并消除代码行号带来的无意义键盘焦点。按用户指定的 **2 → 5 → 6 → 4 → 1 → 3** 顺序实施；每项完成后再开始下一项。保留 MkDocs、`terminal` 主题和 `gruvbox_dark` 配色，不重写已有笔记正文，不引入新的站点服务或测试套件。

前次检查中“搜索完全失效”是误报：自动化工具的 `type`/`fill` 未触发主题监听的 `keyup`。真实按键输入 `Cargo` 可返回 34 条结果；但搜索索引采用英文配置，中文“所有权”确实没有结果。用户确认将第 1 项改为**修复中文搜索，同时保留英文搜索并支持粘贴与输入法**。

项目仅以 `mkdocs build` 作为正式构建验证；浏览器检查用于确认实际布局和交互。内部设计及实施计划放在仓库根目录 `plans/`，不发布到站点。

## 方案取舍

采用最小扩展：在现有侧栏上加移动端折叠入口，以少量 `terminal` 模板覆盖设置语言和图标，中文检索从 MkDocs 现有索引补充结果，英文 Lunr 搜索保持原样。这样变更集中、可逐项回退，并保留主题更新能力。

未采用整体复制主题模板并重写全部搜索：这会扩大维护范围。也不能仅靠配置解决：`terminal` 把 HTML 语言及搜索文案写死；当前安装的 `lunr.zh.js` 在浏览器分词时依赖未提供的 `nodejieba`，单独将搜索语言设为 `zh` 会报错。

## 2. 移动端导航

主题在低于 `70em` 时改为单列布局，侧栏排在正文前；375×812 视口下，“所有权”正文从页面约第 1227 像素才开始。沿用 `docs/collapse_nav.js` 与 `docs/collapse_nav.css`：脚本在侧栏前插入中文目录按钮，按钮通过 `aria-controls` 指向原侧栏，并同步 `aria-expanded` 与可见文字。窄屏默认收起侧栏，点击后在正文前展开，现有分类折叠与当前分类展开逻辑继续使用；桌面布局不变。

仅在脚本完成按钮初始化后才启用隐藏侧栏的 CSS 类，避免禁用 JavaScript 时导航消失。按钮在键盘上可操作；展开后再次点击或按 Escape 可收起。窄屏首页和长篇文章都应在首屏看到主要内容，而不必先滚过整个分类列表。

## 5. 标题、语言与图标

将 `mkdocs.yml` 的 `site_name` 改为“王佳贤的个人博客”。在仓库根目录增加小范围 `terminal` 模板覆盖目录，通过 `theme.custom_dir` 启用：覆盖 `site_lang` 块为 `zh-CN`，覆盖主题固定的图标链接，仅引用 `docs/img/favicon.svg` 中的一枚本地图标；翻译顶部搜索按钮、搜索弹窗、提示与关闭按钮的文案。图标沿用终端风格与现有深色配色，不依赖外部图像服务。

不复制完整 `base.html`。当前 `theme.language: zh` 不会改变主题写死的 HTML 语言和文案，应去掉这一误导性配置；内置英文搜索索引仍保持英文配置，中文检索由第 1 项处理。生成页面不应再引用不存在的 `img/favicon*` 文件。

## 6. 代码标签与发布依赖

将 `docs/MarkDown/MarkDown.md` 中两处 `Markdown` 与一处 `C` 代码块语言改为小写；移除在 `terminal` 中不起作用的 `navigation.tabs`。新建根目录依赖清单，固定已在本地构建的版本：`mkdocs==1.6.1`、`mkdocs-terminal==4.8.0`、`pymdown-extensions==10.21.2`。GitHub Actions 改为安装此清单，不再安装仅为引入扩展而存在的 `mkdocs-material`；部署命令和 `main` 分支触发条件不变。

不引入额外 linter 或测试框架。配置调整后用 `mkdocs build` 确认扩展、模板和主题仍能共同构建。

## 4. 内容入口与排序

保留 `docs/index.md` 的个人介绍，在首页添加直达现有笔记类别的链接，将已标为完成的 Markdown 与 Git 条目改为实际笔记链接，并将“sqlite之类的jj”改为清晰的数据库学习计划。`mkdocs.yml` 中 Rust 内容按基础语法、控制流、所有权和借用、结构体与集合、泛型与错误、模块与项目组织等渐进顺序排列；Git 先“基础概念→初始设置→基本操作”，再进入分支等进阶内容；日期随记按新到旧排列。

`docs/Linux/安全特性.md` 只有标题：保留文件，不编造正文，暂时从导航中移除。其余现有笔记仍保持在手工维护的 `nav` 中，避免因排序而丢失可见页面。

## 1. 中文搜索与输入事件

内置英文 Lunr 搜索不更换。增加一个独立脚本读取现有 `/search/search_index.json`（实际 URL 按 MkDocs 的 `base_url` 计算），仅在查询包含汉字时对页面级文档的标题和正文进行不区分大小写的完整词组包含匹配；标题匹配优先，按页面 URL 去重，最多显示 20 项。此阶段不提供中文分词或多个词组组合搜索。使用 DOM API 设置文本和链接，避免将索引内容拼成不受控 HTML。索引请求只发起一次并复用加载结果，不引入第三方分词依赖。

中文分支监听 `input` 和 `compositionend`，覆盖输入法提交及粘贴；中文查询期间不让主题的 `keyup` 查询及尚未返回的英文 Worker 结果覆盖中文结果。英文键盘搜索继续交给原有 Worker，英文粘贴也应主动触发原有搜索入口。异步请求返回前再次核对当前查询，防止旧结果覆盖新输入；索引加载失败时显示中文错误提示，后续输入可重试。空查询清除结果；包含汉字但少于两个汉字的查询显示输入提示，不扫描全部页面。

浏览器检查至少覆盖英文 `Cargo`、中文“所有权”、粘贴、输入法结束、快速切换中英文、首页及深层文章页的结果链接。前次误报已在临时检查报告中标注撤回，不把它当作英文搜索修复目标。

## 3. 代码行号无障碍

关闭 `mkdocs.yml` 中 `pymdownx.highlight.anchor_linenums` 的代码行锚点选项。目标是消除“所有权”等长篇笔记中大量空名称、可被 Tab 聚焦的 `#__codelineno-*` 链接，同时保留 Pygments 高亮、现有配色和代码复制按钮。浏览器抽查代码块外观、复制交互及键盘焦点顺序。

## 分段验收

每一项按 **2 → 5 → 6 → 4 → 1 → 3** 顺序修改后运行 `mkdocs build`，在对应页面人工复查；失败时先定位该项原因，不把修复混入下一项。最终再次构建，检查首页与长篇笔记在 375×812 和桌面宽度下的表现、中文与英文搜索、站点标题及语言、图标请求、导航内容和代码块焦点。未验证线上部署前，不声称线上效果已确认。
