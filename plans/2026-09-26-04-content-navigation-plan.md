# 第 4 项：内容入口与导航顺序实施计划

> **执行要求：**先阅读设计文档；原生执行使用 `superpowers:executing-plans`，若用户明确选择分代理执行则使用 `superpowers:subagent-driven-development`；逐项勾选步骤。第 6 项完成后执行本计划；完成后才开始第 1 项。

**目标：**首页可快速进入现有笔记，Rust、Git 与随记按易读顺序出现；空白 Linux 笔记不占公开导航。

**架构：**只编辑手工维护的 `mkdocs.yml` 导航和 `docs/index.md`，链接指向已经存在的 Markdown 笔记；空白文件保留，不编写虚构内容。

**技术栈：**MkDocs 1.6.1、Markdown、`terminal` 导航。

**设计文档：**`plans/2026-09-26-mkdocs-site-improvements-design.md` 的“4. 内容入口与排序”。

## 全局约束

- 顺序固定为 **2 → 5 → 6 → 4 → 1 → 3**；本项不处理搜索或行号。
- 保留首页个人介绍和原有笔记正文，`docs/Linux/安全特性.md` 保留文件但从导航移除。
- 新增的首页链接指向已有文件；其余现有笔记继续登记在手工 `nav` 中。
- 页面文字用简体中文；仅以 `mkdocs build` 正式验证构建。

## 重点复核

1. 首页每个新增链接都指向实际笔记：任务 1 步骤 3 浏览器检查。
2. 首页旧的个人介绍没有被删除、`sqlite之类的jj` 已改为清晰计划：任务 1 步骤 3 检查。
3. Rust 与 Git 的每篇现有笔记仍在导航中且无重复：任务 2 步骤 3 检查。
4. 随记按日期从新到旧，无日期条目仍保留：任务 2 步骤 3 检查。
5. Linux 空白页不再出现在导航，但文件未删：任务 2 步骤 3 检查。
