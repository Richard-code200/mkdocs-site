远程仓库操作

管理远程仓库

# 查看远程仓库
git remote
git remote -v # 显示详细URL

# 添加远程仓库
git remote add <name> <url>
git remote add origin https://github.com/user/repo.git

# 修改远程仓库URL
git remote set-url <name> <new-url>

# 删除远程仓库
git remote remove <name>

# 重命名远程仓库
git remote rename <old-name> <new-name>

推送和拉取

# 推送本地分支到远程
git push <remote> <branch>
git push origin main
git push -u origin main # 设置上游分支(首次推送)

# 拉取远程更新(不自动合并)
git fetch <remote>
git fetch --all

# 拉取并合并(fetch + merge)
git pull <remote> <branch>
git pull --rebase # 使用 rebase 而非 merge

# 删除远程分支
git push origin --delete <branch-name>

克隆与同步

# 克隆仓库
git clone <url>
git clone --depth 1 <url> # 浅克隆(只克隆最新版本)

# 同步远程分支
git fetch --prune # 清理本地不存在的远程分支引用

常见问题

SSH 推送时 22 端口连接被关闭

问题现象

使用 SSH 远程地址推送时，出现类似错误：

Connection closed by 198.18.0.5 port 22
致命错误：无法读取远程仓库。

解决方法

先确认 GitHub 登录状态和 Git 用户配置：

gh auth status
git config user.name
git config user.email

如果 gh 已经登录，可以临时使用 HTTPS 地址推送：

git push https://github.com/<user>/<repo>.git <branch>

例如：

git push https://github.com/Richard-code200/mkdocs-site.git main

Git 会通过 gh auth git-credential 获取 GitHub 凭据，不需要把 Token 直接写入命令。

推送完成后，可以通过以下命令确认远程分支已经更新：

git ls-remote https://github.com/<user>/<repo>.git refs/heads/<branch>
git fetch https://github.com/<user>/<repo>.git <branch>:refs/remotes/origin/<branch>
git status --short --branch

mkdocs build 出现链接警告

构建成功不代表所有 Markdown 链接都有效。构建时可能出现以下警告：

  • 文档中的外部链接被误识别为站内相对路径，找不到对应文档。
  • 文档引用了当前页面不存在的标题锚点。

这类警告通常不会阻止站点生成，但应检查链接写法和标题是否确实存在。完成修改后，仍应运行：

mkdocs build

确认最终输出包含 Documentation built successfully 或类似的构建成功信息。
