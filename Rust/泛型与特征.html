单态化(Monomorphization)

Rust 在编译时将泛型代码展开为具体类型的代码:

泛型零运行时开销

单态化发生在编译期,生成的代码与手写具体类型完全一样.因此 Rust 的泛型没有运行时性能损失,这是与 Java/Python 泛型(类型擦除)的核心区别.

运算符特征约束

Rust 中的运算符(+、-、* 等)都是通过特征实现的.泛型函数中使用运算符时,必须用特征约束告诉编译器 T 支持该运算:

  • T: Add 表示 T 必须实现 Add 特征(支持 + 运算)
  • <Output = T> 表示加法结果的类型也是 T(关联类型)
  • use std::ops::Add 将 Add 特征导入当前作用域

use 关键字(导入)

use 用于将其他模块的内容引入当前作用域,避免每次写完整路径:

不加特征约束会报错

编译器不知道 T 是否支持 +,必须显式约束.

泛型排序需要比较元素.项目中的冒泡排序把参数写成 T: Ord,含义是“接受任意类型 T,但该类型必须支持全序比较”:

这里的 > 需要比较能力,因此不能只写 fn bubble_sort<T>.Ord 比 PartialOrd 更强,要求任意两个值都有确定顺序,适合整数和字符串等类型;f32、f64 因为存在 NaN,没有实现 Ord,不能直接传给这个函数.参数使用 &mut [T],所以数组切片和 Vec<T> 切片都能复用同一实现.空切片的 len 为 0,外层 0..len 即 0..0,循环体完全不执行,因此不会计算内层范围中的 len - 1 - i;单元素切片只执行一次外层循环,此时内层 0..0 为空,同样不会索引元素.

特征(Trait)

特征(Trait)定义了类型必须实现的行为.类似其他语言中的”接口”(Interface).

定义特征

  • 使用 trait 关键字定义
  • 内部只声明方法签名,不提供实现(或提供默认实现)

孤儿规则(Orphan Rule)

我可以为自己的类型实现标准库的 trait,或为外部类型实现自己的 trait.但不能为外部类型实现外部 trait,这是为了避免冲突.

dyn Trait:通过共同接口使用具体值

dyn 与测试没有特殊关系.它用于 trait 对象,表示通过某个 trait 的接口使用具体值,调用相应方法时采用动态派发.

以 minigrep 的错误为例,假设已有实现 Error 的 ConfigError:

类型含义
ConfigError具体的错误枚举,可以直接 match 它的变体
Box<ConfigError>拥有一个具体的 ConfigError
Box<dyn Error>通过 Error 接口拥有一个满足约束的具体错误,例如 ConfigError 或 io::Error

Error 是 trait,不是某种具体错误结构.dyn Error 不具有统一的、可直接按值存储的大小,因此通常通过 Box<dyn Error> 或 &dyn Error 等指针形式使用.Box 提供拥有型、大小已知的指针;与借用 &dyn Error 不同,它负责所持值的所有权与释放.这里的装箱错误还需要满足错误处理笔记所述的生命周期约束.

动态派发不是“运行时才确定变量类型”

上面 error 的变量类型在编译期就已确定为 Box<dyn Error>,Rust 仍然是静态类型语言.装入的具体值仍是 ConfigError::MissingQuery.

“动态”描述的是通过 trait 对象调用方法时,运行时选择底层具体类型的方法实现.无论代码在普通函数还是 #[test] 函数中,含义都一样.测试中的 assert_eq! 检查的是消息内容,不是在运行时声明变量类型.

泛型 T: Trait 或参数位置的 impl Trait 通常通过单态化进行静态派发;dyn Trait 提供动态派发.不需要为了“支持多种类型”就到处加入 dyn,应先判断是否需要通过同一个 trait 对象接口持有或借用不同的具体类型.

常用标准库特征

特征用途derive
Display{} 格式化输出不可 derive,需手动实现
Debug{:?} 调试输出#[derive(Debug)]
Clone显式复制或克隆#[derive(Clone)]
Copy隐式按位复制#[derive(Copy)]
PartialEq== / != 比较#[derive(PartialEq)]
Eq标记等价关系,要求自反性#[derive(Eq)],需先有 PartialEq
PartialOrd< / > 比较#[derive(PartialOrd)]
Hash可作为 HashMap 的键#[derive(Hash)]

Clone 的具体语义由类型实现决定,不能一概视为深拷贝.例如 String::clone 会复制字符串缓冲区,而 Rc::clone 只增加引用计数并共享同一份数据.

泛型 + 特征 = Rust 核心范式

泛型提供类型灵活性,特征提供行为约束.两者结合,让我能写出“适用于任何满足条件的类型”的代码,同时保持编译期类型安全和零运行时开销.
