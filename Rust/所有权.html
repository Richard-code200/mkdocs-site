什么是所有权

所有权是确保 Rust 程序安全的一种机制.所谓”安全”,是指程序中没有未定义行为(Undefined Behavior).

未定义行为

当执行一段代码时,结果不可预测且未被编程语言指定的情况.Rust 的基础目标是确保你的程序永远不会有未定义行为,次要目标是在编译时而非运行时防止未定义行为.

大多数语言在运行时才会抛出异常,而 Rust 的目标是尽可能减少运行时的检查——Rust 在编译时就会进行错误分析和抛出.

所有权规则

所有权有三条基本原则:

  1. Rust 中的每一个值都有一个所有者(Owner)
  2. 值在任意时刻有且只有一个所有者
  3. 当所有者离开作用域,这个值将被丢弃(Drop)

所有权是 Rust 最独特的特性

所有权机制让 Rust 无需垃圾回收器(GC)就能保障内存安全.其他语言通过 GC 或手动内存管理来保证安全,Rust 则通过编译期检查所有权规则来实现,真正做到了零运行时开销.

栈(Stack)与堆(Heap)

栈

栈中的所有数据都必须占用已知且固定的大小,数据以”后进先出”(LIFO)的方式管理.

L1(Stack)L2(Stack)L3(Stack)
main(n:5)main(n:5)main(n:5,y:6)
plus_one(x:5)
  • 函数调用时,参数和局部变量被推入栈
  • 函数返回时,其栈帧被弹出,变量随之释放

堆

对于编译时大小未知或可能变化的数据,存储在堆上:

  • 分配内存时,操作系统在堆中找到足够大的空间,标记为已用,返回指针
  • 栈上存放的是指向堆的指针,长度,容量等信息

栈 vs 堆

栈(Stack)堆(Heap)
速度快(直接访问)慢(通过指针间接访问)
大小固定,编译时已知动态,运行时分配
管理自动(LIFO)手动 / 所有权机制
用途简单类型(i32,bool 等)复杂类型(String,Vec 等)

变量作用域

当变量离开作用域时,Rust 会自动调用 drop 函数释放内存.这与 C++ 的 RAII(Resource Acquisition Is Initialization)模式类似.

Copy trait

是否发生隐式复制取决于类型是否实现 Copy trait,而不是值位于栈还是堆.例如整数实现了 Copy,所以赋值后两个绑定都能使用:

如果一种类型实现了 Copy trait,那么赋值后旧变量仍然可用.Rust 不允许自身或其任何部分实现了 Drop trait 的类型使用 Copy.

实现了 Copy 的常见类型:

  • 所有整数类型(u32,i64 等)
  • 所有浮点类型(f32,f64)
  • 布尔类型(bool)
  • 字符类型(char)
  • 元组,当且仅当其包含的每个元素都实现了 Copy
  • 不可变引用 &T

Copy vs Clone

Copy 是隐式的,按位复制,不会影响原值;Clone 通过 .clone() 显式调用,具体克隆语义由类型实现决定.实现了 Copy 的类型通常也实现了 Clone.

String::len 返回字节数

String::len() 和 str::len() 返回 UTF-8 编码后的字节数,不是字符数.例如 String::from("中").len() 是 3.按 Unicode 标量值计数可使用 .chars().count(),但这也不等同于用户感知的字形数量.

引用与借用

每次都要把所有权传来传去太麻烦了.引用(Reference)允许在不获取所有权的情况下使用值:

& 符号表示引用,它允许使用值但不获取其所有权.把创建一个引用的行为称为借用(Borrowing).

借用的比喻

借用的本质是”暂时使用,用完归还”.你不拥有它,只是临时访问.当你用完或引用离开作用域后,借用关系就结束了.

可变引用

默认情况下,引用是不可变的:

可变引用有一个重要限制:在任意给定时间,要么只能有一个可变引用,要么只能有多个不可变引用.

数据竞争

多个可变引用同时存在会导致数据竞争(Data Race),这在 C/C++ 中是 UB 的来源之一.Rust 在编译期就禁止这种情况,从根本上消除了数据竞争.

借用检查器会从引用创建处分析到它的最后一次使用.最后一次使用后借用可以结束,但引用变量所在的词法作用域并没有因此提前结束:

这种按实际使用位置而非仅按代码块边界分析借用有效期的机制称为非词法生命周期(NLL, Non-Lexical Lifetimes).

借用规则总结

  1. 在任意给定时间,要么有一个可变引用,要么有任意多个不可变引用
  2. 引用必须总是有效的(不能有悬垂引用)

悬垂指针:指向已经被释放或分配给其他人的内存地址的指针.Rust 中,编译器保证引用永远不会变成悬垂引用:

编译器会精确分析引用的生命周期,确保任何引用都不会比其引用的数据活得更长.

Box<T> — 堆上分配

Box<T> 是 Rust 中最简单的智能指针(Smart Pointer),它允许将数据存储在堆上,而栈上只保留指向堆数据的指针.

基本用法

Box<T> 的核心特点:

  • 数据在堆上分配,栈上只存指针
  • 遵循所有权规则:当 Box 离开作用域时,它和它指向的堆数据都会被释放
  • 实现了 Deref trait,可以像普通引用一样解引用

Box 的内存布局 

栈(Stack)          堆(Heap)
+------+          +-----+
| 指针 | --------> |  5  |
+------+          +-----+
(一个机器字)       (i32, 4字节)

当 T 是定长类型时,Box<T> 本身通常占一个机器字,实际数据在堆上;具体字节数随目标平台而变化.指向动态大小类型的 Box 可能是包含额外元数据的胖指针,通常占两个机器字.

为什么递归类型需要 Box

List 枚举在编译时需要确定最大变体的大小.如果 Cons(i32, List) 直接包含自身,编译器会陷入无限循环计算大小.Box<List> 通常占一个机器字,具体字节数随目标平台而变化;这层固定大小的间接引用打破了递归.

所有权核心要义

所有权,借用,切片以及 Box<T> 这些概念,都在编译时保障了 Rust 程序的内存安全.Rust 通过所有权系统,让你不需要垃圾回收器,也无需手动管理内存,就能写出安全,高效的代码.
