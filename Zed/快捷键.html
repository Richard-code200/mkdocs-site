~/.config/zed/settings.json 使用 VSCode 基础键位并启用 Vim 模式，通过 vim.toggle_relative_line_numbers: true 在普通模式显示相对行号、插入模式显示绝对行号。未列出的 VSCode、Vim 或 Zed 默认快捷键仍可能有效。

最近核对日期为 2026-09-24，仅核对了本地配置，未逐键实测。冲突和键名疑问列在对应位置。

文本对象、范围编辑与默认 Vim 操作见 Vim 编辑与 Zed Vim 模式。默认键位与本页的自定义绑定可能不同，使用时以实际上下文为准。

按键约定

  • Space 是 Leader 键，例如 Space g s 表示依次按下三个键，而不是同时按下。
  • Ctrl、Shift 是修饰键；Ctrl-Shift-s 表示同时按下这三个键。
  • 空格分隔的按键是连续按键，例如 g r、Ctrl-x Ctrl-o。
  • 大写单键表示配合 Shift，例如 A 等同于 Shift-a，S 等同于 Shift-s。
  • 同一个键可因当前焦点、Vim 模式、菜单状态而执行不同操作；应结合各表的“上下文”列判断。
  • 表中的 | 表示竖线键，\ 表示反斜杠键。

Space e / \Vim 控制状态且无等待/菜单时在项目面板定位当前文件；EmptyPane、SharedScreen、KeyContextView 中切换项目面板焦点；ProjectPanel 非编辑状态中关闭左侧 Dock。
Ctrl-h/j/k/l是无上下文限制的全局窗格导航，可能优先于编辑器、终端或面板自己的同键行为。
Ctrl-enter完整 Editor 且不在 ContextEditor 时接受 Edit Prediction，优先于较早的 Vim 控制状态 null；动作无法处理时，该 null 阻止回落到默认 Inline Assist。更晚的补全与 Code Actions 确认绑定会覆盖预测动作；Terminal 中保持禁用。
ctrl+enter重命名配置使用加号写法 ctrl+enter，不同于其余位置的 ctrl-enter；此处按配置意图记录，当前 Zed 版本能否识别仍需按键实测。
j j / j k退出插入模式的配置块已整体注释，当前不生效。
Git 面板的 q / EscapeGit 面板当前在右侧，但动作仍切换左侧 Dock。
c a打开 Code Actions，会影响传统 Vim 的 c a … 文本对象序列。
s / S普通与可视模式中启动 Sneak，需要继续输入两个目标字符。

此外，Editor && VimControl 中的 Ctrl-c 会发送 Escape；插入模式与 Inline Assist 又分别将它映射为返回普通模式和取消辅助编辑。具体执行哪个动作由最匹配的上下文决定。

常用操作流程

以下流程中的箭头表示操作步骤，不是额外按键。

场景操作步骤
查找文件并编辑普通模式 → Space s f → 输入文件名并打开 → i 进入插入模式 → Ctrl-s 保存
手动触发并确认补全插入模式 → Ctrl-x Ctrl-o → 选择候选项 → Ctrl-y 确认；Enter 在补全菜单中绑定为换行
重命名符号普通模式，将光标放在符号上 → Space r n → 输入新名称 → Enter 确认
处理诊断普通模式 → ] d / [ d 定位 → Space c a 打开 Code Actions → 选择操作 → Ctrl-y 确认
复制到外部程序可视模式选中文本 → g y → 在目标程序中使用其粘贴快捷键
插入模式粘贴Ctrl-Shift-v；Ctrl-v 在这里用于输入字面字符
查看并暂存改动普通模式 → ] h / [ h 定位 → Space g d 查看 Diff；回到编辑器后用 Space g s 切换暂存状态
使用内置终端Ctrl-\ 切换底部 Dock → 终端获得焦点后用 Ctrl-Shift-o 新建终端、Ctrl-Shift-h/l 切换标签

配置维护

  • 自定义键位来源：~/.config/zed/keymap.json。
  • 面板位置来自 settings.json：当前 Project 为左侧，Git、Agent、Outline 和 Collaboration 为右侧。排查 Dock 快捷键时应同时核对动作方向和面板位置。
  • 基础键位、Vim 开关和普通/插入模式相对行号切换来源：~/.config/zed/settings.json，其中 vim.toggle_relative_line_numbers: true。
  • 修改配置后，应重新逐项检查上下文条件、空绑定 null 和被注释的代码，避免把禁用项误写成有效快捷键。
  • 在命令面板运行 zed: open default keymap 可查看当前 Zed 版本的默认键位，并与自定义覆盖进行对照。
  • 外部任务快捷键失效时，应同时检查 Zed 任务定义、任务名称以及任务定义声明的实际命令和依赖，而不应只检查 keymap。
